## roachHub 蟑螂肢体动画改造（完成）

**背景**：原来 `Cockroach.render()` 只是 `drawPixmap(整张写实贴图) + 两条 quadTo 触须`，
腿与触须烘焙在照片里，无法活动；且照片自带触须与代码矢量触须叠加成"四根触须"。

**方案**：改为运行时程序化骨架（不是序列帧）。
- 新增 `src/animation/`：`pose.py`(PoseBlender 指数平滑) / `gait.py`(LegRig 三足步态+两段式 IK)
  / `antennae.py`(AntennaRig 7 段链+行波+滞后追随)。
- `src/entities/cockroach.py` 重写 update/render：状态→姿态目标→平滑→骨架→绘制；
  绘制顺序 阴影→六足→躯干→触须→交配特效。
- 新增 `tools/build_body_sprites.py`：把照片拆成「纯躯干」贴图（参数化轮廓 + 轮廓外洪泛 +
  纵向短段去残茬），生成 `assets/sprites/*_body.png`(成人 117x215 / 若虫 92x184 / 蜕壳 90x220)。
  若虫、蜕壳源图是 3/4 侧视，需先旋转（103°/117°）转正。
- 新增 `tools/preview_animation.py`(帧表 + CSS 逐帧 HTML)、`tools/gait_diag.py`(足端轨迹诊断)、
  `tools/smoke_test.py`(离屏 180 tick + 性能基准)。
- 动态 LOD：`Cockroach.quality` 由 `app._on_tick` 按同屏数量设置（>110→0，>55→1）。
  实测 50 只 ~18ms、150 只 LOD0 ~31ms。

**文档**：`docs/animation-system.md`（实现与参数）、`docs/fun-features.md`（5 个趣味性方案评估）。

**已知限制**：若虫/蜕壳贴图非纯俯视；躯干侧缘仍残留 2~3px 足基；支撑相是等效处理，
急转弯可能有极轻微滑步。

**未做（等确认）**：足迹痕迹、抓取挣扎、进食过程、程序化音效。

## roachHub 趣味性五方案落地（完成，用户明确要求"扰民/脏屏全保留"）

**修掉的致命 bug**：`app._on_tick` 从未调用 `entity.update(dt)` —— 上一轮的肢体动画在真实
运行里等于零，且 `FREEZE.freeze_timer` 永不递减导致近距离永久僵直。现为 step3，顺序：
behavior → movement → entity.update → needs。

**新增能力**
- 触须跟随：`threat_vector` 常驻、`threat_proximity` 分段映射、权重 `0.30+0.70·prox+0.25·alert`。
  关键认知：**姿态层每帧从基线重算，"权重插值"≠"持续跟随"**，朝向类参数必须区分基线与当前值。
- 痕迹层 `src/systems/trails.py`：1:1 分辨率（实测比半分辨率**更快**，省一次双线性放大）。
- 拖拽 `EntityState.DRAGGED` + 临界阻尼弹簧(k=260) + `flail` 姿态通道
  （`anchored=0` 不会蹬腿，因为 `moving = speed>2 and anchored<0.95`）。
- 进食：停距 `max(32, 0.62×体长)`（首版 20px 被躯干遮住）、位点用 2.5s 心跳 TTL。
- 音效 `src/systems/audio.py`：标准库现场合成 WAV，四层限流（采样→预算→池轮转→距离衰减）。

**两个量化/数学陷阱（易复发）**
1. `CompositionMode_DestinationOut` 在 8 位合成器上是 `round(dst·(1-a/255))`，逐帧小量衰减会被
   舍回原值（卡在 alpha=11）。必须**累加**到 ≥0.16 再统一填充。
2. 两根触须 `aim ± 0.22`，期望方向在 ±π 附近时朴素平均产生假 180° 误差，验收要用圆周平均
   `atan2(Σsin, Σcos)`。曾表现为测试约 50% 概率随机失败。

**验收**：`tools/interaction_test.py` 15/15 PASS（触须 13.5~18°、拖拽 9.1px、松手 470px/s、
装死 6.6s、进食 40→75、3s 74~76 足印、16s 归零、音效恰好 10 次/秒）。
痕迹开销 1920×1080/2355 笔 ≈ 0.5~0.7ms/帧。

**文档**：`docs/interactions.md`、`docs/fun-features.md`（改为"评估与落地记录"，含与原方案的偏差）、
`docs/animation-system.md`（15 姿态通道）、`README.md` 第 6 节。

**注意**：离屏平台无字体库，验证图**不能 drawText**（会渲染成方框），用版面顺序表达。

## 抓取音效「你干嘛」（完成）

**需求**：捏住/拖动蟑螂时播放用户给的 MP3。

**素材真相**：132KB / 16.95 秒，但**有声内容只有 0.08~3.88 秒**。
MP3 是 CBR 64kbps，**数字静音同样按 209 字节/帧占位**，13 秒空白吃了 79KB。
判断有效区间只能扫能量阈值，不能信容器时长。

**关键决策：构建期裁切，不在运行时播 MP3**
`QSoundEffect` 只吃 WAV；MP3 要走 `QMediaPlayer`，启动延迟 100~300ms，抓取等不起。
`tools/prepare_voice.py`：解码 → 裁 0.17s+3.45s → 12ms 淡入/120ms 淡出 → 峰值归一化 →
`assets/sounds/grab.wav`（22050Hz 单声道 149KB）。**松手默认不打断**（`grab_voice.stop_on_release`），
因为整句 3.45s 而实际拖拽只有 0.3~0.8s，一松手就掐会让「哎呦」永远听不见。

**重要教训：句子边界不能看能量谷，要看基频**
第一版按 20ms 能量包络切 0.20s+1.76s，把 1.88~2.12s 判成"换气间隙"，结果「哎呦」整段丢失
（用户指出）。原因：说话停顿只掉到 -25~-30dB，比静音阈值高得多；而拖长单音能量近乎恒定，
反而像伴奏。可靠依据是自相关基频：浊音置信度 >0.55、F0 130~340Hz。
`tools/voice_sections.py` 按此分段：0.18~0.29(你) / 0.32~2.12(你干嘛) / 2.22~3.18(哎——) /
3.21~3.62(呦) / 3.77~3.90 只是 -32dB 混响尾巴。**以后改裁切窗口先跑它**。
`tools/voice_preview.py` 生成 `tools/out/voice_preview.html`：波形+浊音段标记+3 个版本可试听
（内嵌 base64 WAV），改完不必靠猜。

**踩到的坑**
1. `QAudioDecoder` 在这个构建里把输出**补零到固定总帧数**（16.95s 解成 56s），
   不能拿总长度判断有效区；`QMediaPlayer` + `/tmp` 假路径也会 "Could not open file"（MSYS 路径）。
2. 测防抖时**不能替换 `play` 本身** —— 会把被测逻辑一起换掉，永远"每次都响"。要打桩 `_effect`。
3. 加了 `_is_broken()` 后桩对象缺 `status()` 被误判为损坏 → 改成"没有 status 就当没坏"。

**接线**：`OverlayWindow(on_grab_started=...)` 在 `begin_drag` 后回调 → `app._on_grab_started`
→ `grab_voice.play()`；`on_entity_dropped` → `stop()`。托盘总静音一并压掉（同时把菜单文案
改成"全部音效"）。配置 `[grab_voice] enabled/volume/file`；设置面板新增分组 + 试听按钮。

**独立模块** `src/systems/voice.py`：触发频率、素材形态、是否需要限流、音量级别、用户容忍度
五项都与 `ScuttleAudio` 不同，只有总静音耦合。

**验收**：`interaction_test.py` 扩到 **20 项全绿**（新增 5 项：素材就绪 / 按下播松手停 /
总静音不出声 / 120ms 防抖 / 允许重播）。

## 闪烁 + 卡死定位（完成）—— 50 只就卡，要求 200 只不卡

**用户的原始描述**：不到 50 只蟑螂屏幕直接闪烁并卡死，要求 100~200 只也必须流畅。

**三个独立原因，全部命中**

1. **每帧 `QRegion` + `setMask()` —— 闪烁的真凶。**
   为了让"空白处点击穿透"，`paintEvent` 里每帧按实体包围盒重建 region 再 `setMask`。
   Windows 上每次 `SetWindowRgn` 都会触发 `WM_WINDOWPOSCHANGING` 级别的形状重排 + 整窗重绘，
   33 次/秒等于**自己给自己制造闪烁**；顺带把超出 region 的肢体剪掉、足迹层被裁没、
   桌面在蟑螂之间的空隙点不动。
   改用 **`WM_NCHITTEST` 原生事件过滤器**返回 `HTTRANSPARENT`：零 region 重建，
   系统只在鼠标真的落在窗口上时才问，空白处 Windows 自己跳过（实测查询次数 = 0）。
   非 Windows 保留 4Hz 的 mask 兜底（`tick_mask`）。
   → 这正是"蟑螂越多越闪"的原因：region 里有 N 个矩形，重排代价随 N 飙升。

2. **`QTimer` 默认 `CoarseTimer` 把 33.3ms 量化成 46.6ms。**
   Windows 15.6ms 时钟粒度下，粗定时器会向上取整到 3 个 tick → 30 FPS 变 21 FPS，
   而且周期抖动。改 `setTimerType(Qt.TimerType.PreciseTimer)` 后 p50 回到 33.03ms。
   **以后凡是对帧率有要求的 `QTimer` 都必须显式设 PreciseTimer。**

3. **事件循环饱和 = 用户口中的"卡死"。**
   帧耗时 > 定时器周期时，任务队列永远是满的，鼠标/托盘/右键全部无响应；
   但任务管理器只看到 13% CPU——**这不是 CPU 忙，是主线程被自己的 repaint 堵死**。
   诊断必须看"帧间隔 p95/最大值"，不能看 CPU 占用。
   为此重写 `_govern_frame`：区分 **期望预算 `1000/target_fps`** 和 **底线 `1000/min_fps`**。
   见底之后先掉画质（LOD2→1→0），画质见底才按 `ema×1.12` 降频，且永远不低于 `min_fps`。
   早期版本把 16.7ms 同时当期望和底线，200 只时明明 33ms 却被自己压到 14 FPS——**自适应器会自造卡顿**。

**每帧开销实测（200 只，离屏）**：
behavior 0.36 / movement 1.45 / entity.update 7.43 / needs 0.08 / trails 1.25 / hit test 0.08 /
render 10.81 → 合计 **21.4ms**，预算内。

**单只绘制拆解（200 只场景）**：LOD2 52.96ms（六足 24.73）；LOD1 46.97；LOD0 36.99
（六足 11.22 / 阴影 6.32 / 触须 4.85 / 躯干 4.02）。

**真机浸泡（2560×1440 真窗口）**：
- 50 只 LOD2 → **56 FPS**，p95 19.0ms
- 100 只 LOD1 → **32.6 FPS**，p95 35.0ms
- 200 只 LOD0 → **30.5 FPS**，p50 32.8 / p95 34.4 / max 35.0，**0 次 >250ms 卡顿**，mask 为空

**关键方法论：离屏测不出窗口合成的 ~7ms。**
`QT_QPA_PLATFORM=offscreen` 下 `repaint` 耗时显示 0.0ms，因为它根本不经过 DWM 合成。
真实一帧 = 主循环 11ms + 绘制 15ms + Qt 清理/合成 ~7ms ≈ 33ms。
**要判断"会不会卡"，必须跑真窗口 soak（`tools/soak_test.py`），离屏只能测 CPU 侧算法开销。**

**顺手修掉的隐性开销**
- `QSystemTrayIcon.setToolTip` 每帧调用 → `NOTIFYICON_MODIFY` 一次 5~30ms → 限频 0.5s。
- 足迹改为批量落章（队列 + 每 tick 一次 `QPainter`），`count` 随淡出衰减、另设 `total_prints`
  给测试用（否则淡出会让断言飘）。
- 群体分离从 O(n²) 改空间哈希 3×3 邻域。
- IK 去掉 `hypot`/`atan2`，`cos(base)=dx/d` 免一次三角；触须点数组预分配复用；
  步态 `exp(-dt/0.045)` 提到循环外。
- LOD0 只关矢量肢体的 AA，保留贴图与触须的抗锯齿（实测腿无台阶）。

**工具**：`tools/soak_test.py`（真窗口浸泡，判据 p95 ≤ floor×1.30）、`tools/perf_probe.py`
（分阶段帧预算）、`tools/render_breakdown.py`（单只绘制拆解）、`tools/sim_profile.py`（cProfile tick）。
文档 `docs/performance.md`，`README.md` 第 7 节；验收 `interaction_test.py` 扩到 **31 项**
（新增点击穿透 / 帧率底线 / 命中测试 <0.5ms / 音效尾音长度）。

**坑**：`QRegion` 在 `QtGui` 不是 `QtCore`；`QRegion.rects()` 不存在；`RoachApp` 需要传 `qapp`；
`TrailCanvas` 的 `_pending_*` 必须在 `resize()` 之前初始化（resize 会清队列）；
`_govern_frame` 单测喂 12 帧不够（EMA 0.88 太黏），要 40 帧才降级、600 帧才恢复。
