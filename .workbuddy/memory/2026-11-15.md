# 2026-11-15

## roachHub 控制台化：启动即开、全局热键、虫巢爆发、批量投放（完成）

**用户诉求（三条）**
1. 每次启动默认打开控制台，而不是去右下角点托盘菜单；
2. 参考微信，可配置快捷键 **隐藏/打开控制台**；
3. 控制台加「虫巢爆发」一键刷满屏，并支持批量加蟑螂（原来只能投放一只 / 一块碎屑）。

**关键发现：原来那两个热键是假的。**
`app.hotkey_toggle_visible / hotkey_open_settings` 从第一版起就只写进了配置与 UI，
**从来没有注册过**，因为 Qt 的 `QShortcut` 只在应用有焦点时才有用。所以这次是补实现，不是改配置。

### 1. 全局热键（`src/utils/hotkeys.py`）
- Win32 `RegisterHotKey(None, id, mods|MOD_NOREPEAT, vk)`，热键注册到**当前线程**。
- **坑 1**：`WM_HOTKEY` 走线程消息队列，Qt 交给 native filter 时 eventType 是
  `windows_dispatcher_MSG`（不是 `windows_generic_MSG`）。只判后者永远收不到。
- **坑 2**：热键系统独占，重复/被占 → 返回 0 + `GetLastError()=1409`。必须把原因告诉用户。
- **这台机器 `Ctrl+Alt+W` 已被占用（1409）**，很可能就是微信自己。所以默认改成
  `Ctrl+Alt+R`（console）`Ctrl+Alt+H`（hide）`Ctrl+Alt+B`（burst）；用户若要微信同款，
  填 `Ctrl+Alt+W` 会看到「已被其他程序占用」而不是静默失效。
- 解析要求**至少一个修饰键**：裸字母注册成全局热键会吃掉全系统的该键。空串 = 禁用。
- **坑 3（自吞噬）**：在 `QKeySequenceEdit` 里录制"显示/隐藏控制台"的热键时，按下当前组合键
  会让窗口当场把自己藏起来。`app._guarded()` 在"设置窗是活动窗口且焦点在 QKeySequenceEdit"
  时丢弃该次热键。**凡是"录制自己"的功能都有这个死循环，要专门挡住。**
- 真机验证：合成 `Ctrl+Alt+R` 三次 → 可见/隐藏/可见，全部符合。

### 2. 虫巢爆发与批量投放（`src/app.py`）
- 语义：**补满，不是重置**（用户已养了 50 只，要"再来一波"，不是清零重来）。
- `BURST_HARD_LIMIT = 400`：防止 `max_roaches` 被填成 9999 时一键打死机器。
- 爆发统一走 `_burst_panic()`：以**屏幕中心**为惊源 `trigger_freeze_and_panic(2.6)`，
  瞬间僵直 0.1s 后四散；音效只响一次。满员时返回 0 但**仍然会炸**。
- `spawn_batch(count, stage, panic)` 不能直接循环 `spawn_cockroach()`：后者每只打一条 INFO
  并刷新托盘 tooltip（`NOTIFYICON_MODIFY` 单次 5~30ms），150 只就是 150 行日志 + 150 次重绘。
  加 `announce=False`，最后统一刷新一次。
- 容量截断：请求 999 只剩 150 空间 → 放 150。200 只全新建构实测 15.3ms（贴图有缓存）。

### 3. 控制台
- 7 个页签，0 号页「🪳 控制台」放即时动作（状态进度条 / 爆发 / 批量 / 清场 / 显隐），**不需要保存**；
  底部 toast 反馈 4 秒，不弹模态框。
- **保存后不再关窗**（它是面板不是对话框）；只有"热键没注册上"才弹窗并列出失败原因。
- 页签在 700px 宽时被挤成 `◀ ▶` 滚动箭头 → 窗口加宽到 880 并缩短标题，7 页平铺。
- 托盘单击 = 召唤控制台（微信习惯）；双击不再绑动作（Qt 会先发 Trigger，两个动作叠加只会困惑）。
- `showEvent` 里立刻刷一次状态，别让用户对着「0/0 只」等半秒。

### 4. 启动时打开控制台会污染帧预算
建窗口 + 首次布局卡消息循环上百毫秒，实测日志出现 `帧耗时 48.7ms → 画质降到 LOD1`，两秒后恢复。
加 `reset_frame_governor()`（EMA 归位到预算、清连击、重置 `_last_tick_time`），
在 open_settings / 应用配置后调用。改完启动日志里不再有假降档。

999 截断到 200、爆发一次刷满、200/200 处于 PANIC、再爆不重复、仍守 min_fps、托盘入口）。
真机：启动 3 热键全注册、控制台可见；爆发到 200 只后 `soak_test --count 200` → 31.3 FPS，0 次卡顿。

## 17:30 「托盘点了没反应 / 右下角整块卡住」——覆盖层在抢点击

用户报：点右下角托盘图标不出控制台，"整块右下角好像卡住、什么都点不了"。

### 定位（用 WindowFromPoint，比猜快得多）
`WindowFromPoint` 内部走真正的 WM_NCHITTEST，直接告诉你"这个点的鼠标归谁"：

| 位置 | 结果 |
| --- | --- |
| 空桌面 / 空托盘 | `XZDesktopWnd` / `TrayNotifyWnd`（正常） |
| 托盘位置放一只蟑螂 | **覆盖层窗口** ← 点击被吃掉 |
| 控制台面板 + 一只蟑螂 | **覆盖层窗口** ← 按钮点不动 |

根因：覆盖层 2560x1440 **连任务栏一起盖住**。空白处 alpha=0，Windows 自己跳过；
但有虫的像素会走 `WM_NCHITTEST`，我们答"归我"，于是托盘/面板的点击被吃掉。
200 只时几乎任何位置都有虫，观感就是"整块区域死掉"。**与 CPU/帧率无关**（当时 loop MAX 22ms）。

另外两个叠加因素：
- 托盘单击走的是 `open_settings`（幂等），但**面板从启动就开着**，用户点它当然"没反应"；
  且 `show()` 对"已可见但最小化"的窗口是 no-op，最小化后永远叫不出来。
- 用户机器上曾同时开两个 `main.py`（两个一样图标 + 两个覆盖层互相抢点击）。

### 修法
1. `overlay._work_rect`（`screen.availableGeometry()`）：`hit_test_at()` 第一道闸门 —— 不在
   工作区一律不认。蟑螂照样能爬到任务栏，只是那里不接管鼠标。
2. `overlay.set_hole_rect()` + `paintEvent` 的 `setClipRegion(整屏-洞)`：控制台 `move/resize/
   show/hide` 发 `geometry_changed` → `app._sync_console_hole()` 换算 `frameGeometry+4px`。
   **挖洞而非置顶**：两个 topmost 谁在上取决于谁最后激活，点一下虫子就会翻上去；挖洞与 z-order 无关。
   `_clip_region` 预计算，每帧只一次 `setClipRegion`，不是每帧重建窗口形状（那才是当初闪烁的根因）。
3. `summon_console()`：托盘单击/菜单 = 幂等召唤（还原最小化 → show → raise → activate）；
   `toggle_console()` 只给热键用；"可见但最小化"按不可见处理。
4. `src/utils/single_instance.py`：`QLockFile`（存 PID，能识别崩溃残留）+ 命名管道唤醒。
   **踩坑**：不能用 `QLocalServer.listen()` 的成败当占有标志 —— Windows 同名管道允许多监听，
   实测第二个进程 `listen()` 也返回成功，守卫等于没做。

### 验收
- `interaction_test.py` **61 → 68 项全绿**（新增 7 条：工作区内可抓 / 任务栏不接管 / 洞口不接管 /
  绘制同步挖空 / 收起后洞清掉 / 召唤可见 / 最小化后能还原）。
- 新工具 `tools/click_route_check.py --count 200`：托盘→`TrayNotifyWnd`、任务栏→`MSTaskSwWClass`、
  面板→控制台窗口，**全部符合预期**。
- 双启动：第二实例 290ms 退出，第一实例日志 `收到二次启动请求，召唤控制台`。
- `soak_test --count 200`：30.4 FPS、p95、0 次 >250ms 卡顿；真机截图确认面板上一个虫都没有。

## 17:45 「蟑螂跑到屏幕中间就消失」——洞只跟位置走，没跟 z-order

用户报：满屏蟑螂，中间一块矩形里虫子**走进去就凭空消失**，走出来又出现。
截图量出来的空白矩形 ≈ 控制台面板的几何（1920x1080 屏上 x552..1344 / y130..860）。

根因：洞是按 `frameGeometry` 挖的，只跟面板**位置**有关，与它**是否露在最前面**无关。
控制台是普通窗口，用户点一下浏览器（maximized）就把面板压到后面 → 面板看不见了，
洞还在原地 → 屏幕上只剩那个洞。

### 修法
1. 新增 `src/utils/win_occlusion.py`：`covered_rects(hwnd, panel)` 用
   `GetTopWindow`/`GW_HWNDNEXT` 从 z-order 顶部往下走，**遇到面板句柄就停**；
   只算可见、未最小化、非本进程的窗口，跳过 `WS_EX_TRANSPARENT`/`WS_EX_NOACTIVATE`。
   必须 `IsWindow(hwnd)` 先兜底 —— offscreen 平台给的是假句柄，否则"没找到"会被当成
   "被所有窗口挡住"，测试环境里洞永远为空。
2. `overlay` 的洞从 QRect 升级成 QRegion（`set_hole_region`）：半遮挡时只让出露出来的那部分；
   全遮挡 → 空区域 → 整屏归蟑螂。
3. `app._sync_console_hole()` 先减遮挡矩形，再转本地坐标；新增 250ms 轮询（`_console_hole_timer`）
   + 设置窗 `changeEvent` 的 `ActivationChange/WindowStateChange` 即时触发 + `raise_()` 后 60ms 补算一次。
4. 顺手修同源坑：**可见但被压住时按 `Ctrl+Alt+R` 会把面板藏起来**。
   `toggle_console()` 改用 `console_in_front()`（可见且没被压住）判断 —— 压着就召唤，真看得见才收起。

### 验收
- `interaction_test.py` 68 → **71 项全绿**（新增：半遮挡只挖右半边（命中+绘制）、完全压住时洞消失）。
- 新工具 `tools/hole_check.py`（真机，8 项全过）：面板在前=面板矩形 / 完全压住=None /
  重新召唤=恢复 / 左半压住=只剩右半边（1278..1723）。
- 真机截图确认：白色遮挡窗口上照常画虫子（此前是整块空白）。
- `soak_test --count 200`：30.3 FPS、p95 16.4ms 绘制、0 次卡顿；`smoke_test` 无异常。

## 白色蟑螂是"刚蜕壳"，不是贴图错误

用户报"白色蟑螂鼠标移上去就变成正常颜色"。定位结论：白 = 蜕皮后的 teneral 嫩壳
（`molt_timer > 0` 时用 `cockroach_white_body`），窗口固定 2.2s，到点必变棕；
鼠标不参与变色 —— 用户看到的"碰一下就变"是 2.2s 计时到点的巧合（同屏 200 只时
任何时刻约 12% 是白的，instar_duration=18s）。

顺带修掉两处真实穿帮：
- **硬切贴图** → `teneral_timer`（2.2+1.4s），结束后白贴图以 smoothstep 递减
  alpha 叠在正常贴图上，颜色是化开的；
- **软壳会狂奔**：蜕皮中仍被鼠标惊吓，以 430px/s 冲刺还顶着蜕皮姿势 →
  `_handle_cursor_perception` / `begin_prestartle` / `trigger_freeze_and_panic` /
  `end_drag` 全部按 `molt_timer > 0` 短路，软壳只能原地待着。

新增 `src/entities/exuvia.py`：蜕下的空壳留 10s 淡出，`interactive=False`
（命中测试与 QRegion 遮罩都跳过），不占 max_roaches。渲染排在痕迹之上、食物之下。
开关：`render.show_teneral`（控制台 → 🎨 表现风格）。

验收：`interaction_test.py` 82 → **92 项全绿**；`smoke_test` 无异常；
`soak_test --count 200` 仍 30.4 FPS / 0 次 >250ms 卡顿。
`hole_check.py` 本会话 5/8（"面板被完全压住"用例依赖真桌面 z-order，与本次改动无关）。
对照图：`tools/molting_preview.py` → `tools/out/molting_preview.png`。
