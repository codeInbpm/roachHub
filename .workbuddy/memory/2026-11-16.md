## 苍蝇拍 / 蟑螂拍设计方案（docs/swatter.md）

用户要求：加苍蝇拍，能拍死蟑螂，带爆浆特效，先出方案。

- 输出 `docs/swatter.md`（16 节，未实现，等拍板）。
- 核心结论：必须做成**显式的持拍模式**（托盘 / Ctrl+Alt+S），因为现有架构只在蟑螂身上
  接收鼠标（`WM_NCHITTEST` + HTTRANSPARENT），空桌面挥拍根本收不到事件。
- 三条硬约束（读代码得到）：
  1. `overlay.hit_test_at` 返回实体、`ClickThroughFilter` 只吃 bool → 必须新增
     `accepts_mouse_at()`，否则空拍点击会穿透到桌面框选图标。
  2. `EcologySystem` 会在 `is_alive=False` 的下一帧删除实体 → 尸体必须是独立实体
     `SquashedRoach` 且 `is_alive=True` 自管 22s 寿命（同 Exuvia 套路）。
  3. `paintEvent` 按 `entity.__class__.__name__` 分发 → 新实体必须显式加进绘制链，否则静默不显示。
- 其他设计决定：判定半径 44+0.3×体长（必须 ≥ 惊恐半径 55，否则"贴上去它反而跑"）；
  70ms 下压 / 200ms 恢复 / 280ms 冷却；爆浆 7 层（污渍/尸体/颗粒/冲击环/白闪/震屏/惊逃）；
  震屏只 translate 绘制、不动 pos；拍面半透明网格（能看见底下的虫）；Esc 收不到（overlay 不抢焦点）。
- 实现未开始。README 尚未更新（实现时补功能一览第 9 条附近）。

## 苍蝇拍：实现完成（P0 + P1）

用户确认方案后一次性落地。新增 `src/entities/squashed.py`、`src/systems/splatter.py`、

落地时**与方案不一致的四点**（都是有原因的，已写进 docs/swatter.md §17）：
1. 颗粒绘制成本被低估一个数量级（240 颗 3.9ms）。三个优化后 1.09ms：颗粒关 AA、
   黏丝只给 `r>=3.2` 的颗粒、QBrush/QPen 按 (色号, alpha 量化档) 缓存。
2. 白闪从 α0.42/54px 收到 α0.20/38px —— 浅色桌面上加法混合会糊成一团白。
3. 尸体的污渍 path 必须 `setFillRule(WindingFill)`，默认奇偶规则会把重叠圆掏空成花瓣；
   六足要画在躯干之前，否则变成压在尸体上的几条线。
4. 闲置收拍口径改为"没挥拍**且**光标没动"，蹲着瞄半分钟被收拍比桌面点不动更恼人。

实测：36/36 验收通过；240 颗粒 1.09ms、拍子 0.43ms、同帧 3 杀结算 0.52ms；
200 只基线 tick 9.38ms，持拍连拍 9.14ms（无恶化），最差单帧 14.87ms。
既有 `interaction_test.py` 94/94（同步改了"四个热键"与"八个页签"两条断言，

## 繁衍系统改造（E 方向：性别与交配真实感）

用户先问"现在怎么繁衍/速率如何/能从哪些角度改"，给了 A~F 六个方向，选了 **E（性别与交配）**。

**改造前实测**（tools/repro_probe.py，真实系统）：无敌食物 101 鞘/min、195s 撞 200 上限；
自然食物 5.1 鞘/min、稳态 20~40 只。瓶颈是食物能量（3.33 能量/s），不是冷却。

**发现的硬 bug**（都写进了 docs/reproduction.md）：
1. `interrupt_mating()` 只清 partner_id 不清 state → 被打断/伴侣被拍死后雌虫永久卡 MATING。
2. behavior `_update_cockroach_behavior` 没有 MATING 分支 → 几秒内把交配状态改回 WALK，
   `mating_progress` 永远走不完，有性模式基本产不出卵鞘。
3. 光标感知 r_mid(120px) 无条件 `state = WALK` → 鼠标停附近 = 全场停产。
4. 对接距离写死 26px，虫体 70px → "尾对尾"其实叠在一起。
5. auto 模式 `adults` 不筛性别，雄虫也产卵；`female_ratio`/`mating_search_radius` 是死参数。

**新模型**（两条硬规则）：只有雌虫产卵 + 必须先受精（`BaseEntity.broods_left`，0=处女）；
一次交配支撑 `fertilized_broods`(2) 次产卵。auto/sexual 只差仪式：auto 1.30×半体长和 ≈91px、
1.5s；sexual 0.92× ≈64px、2.2s。雌虫只在 mating_search_radius 内发现雄虫，**雄虫按信息素
全场搜索**（否则随机散落开局会停摆）。求偶经 `Cockroach.mate_seek` 交给 behavior 落地
（优先级：惊慌>僵直>梳理>蜕皮>进食>交配>求偶>漫步）。
每帧 `_repair_pairs()` 兜底：任一方死亡/受惊/被拎走，另一方立刻回 WALK。
配对扫描节流 0.25s（200 只实测繁殖 0.14ms/帧）。

**改造后实测**：无敌食物 13 鞘/min、240s 到 85 只；自然食物 2.8 鞘/min、稳态 10~25 只；
真实主循环 150s 从 3 只长到 22 只，"待受精"0~4 波动。

**接线**：投放的雌性成虫带 1 次额度（野生成虫多半已交配），卵鞘孵出的个体是处女；
console_stats 加 `unmated`，状态栏在 >0 时追加「待受精 ♀N」；设置页加 3 个参数
（单次交配可产卵次数 / 简化交配耗时 / 尾对尾交尾耗时）并改写模式与感应距离文案。
新增 `tools/reproduction_test.py`（30 项）、`docs/reproduction.md`。
验收：reproduction 30/30、interaction 94/94、swatter 50/50、smoke OK。

**坑**：离屏测 world 必须先在 main 里建 QApplication，否则 `Cockroach` 取 QPixmap 直接 abort（exit 127）；
`RoachApp._on_tick` 用真实墙钟算 dt，跑仿真要塞 `_last_tick_time = perf_counter() - 1/60`，
否则 7200 次 tick 只推进 1 秒。

## 进食位形：虫停在食物边缘（续）

食物半径换成照片贴图后跨度到 17~34.6px，旧的固定停靠距离 `max(32, body_len*0.62)≈43`
让虫整只压在 69px 的腐肉上。改为按食物**实时半径**算停靠环：

    mouth = roach.body_len * 0.52 * roach.scale      # 体心→口器
    ring  = max(26.0, mouth + food.visual_radius * 0.70)
    food.visual_radius = kind.radius * (0.45 + 0.55 * ratio)

系数 0.70 是看图定的：0.58 头埋进食物、三只同吃把腐肉完全挡住；0.80 只剩天线尖碰一下。
判定圈 5px（9px 时收速滑 5px 会停在环外一格，小食物口器悬空）。

**让位**：`eating_slots` 只管数量不管方位，三只同向走来的虫会叠一坨。
每只虫进两倍环后挑"空位方位角"：`Food.open_slot_angle(from_pos, extra_taken)`
转圈取 24 样本选与已占夹角最大的；已占 = 在吃的（`Food.slot_angles`）+ 在路上预定的。
角度钉在 `BehaviorSystem._slot_aim[roach_id]=(food_id, ang)` 逐帧复用——每帧重算会随
身体绕行抖动，表现成原地左右摇摆；只在被别人占了（夹角<0.7rad）时重选。
预定按食物分桶 `_slot_reserve[food_id][roach_id]`，否则 200 只虫退化成 O(n²)。
`_drop_aim()` 吃上/放弃时退位，空桶即删。

**实测**：三只同吃蛆团最近两虫 14.5px → 42~73px；腐肉口器停在 27.5px/半径 34.5，
跳蚤 15.5px/半径 17；90s 40 只虫长跑进食 76 次、吃光 39 块、零饿死、均能量 89.9。
perf：200 只 behavior 0.40ms/帧（未变）。

**验收**：food_test 54→64 项（新增第 7 组"停靠距离与进食位点"），
其余 smoke / interaction 94 / reproduction 30 / swatter 50 全过。
food_preview 增出 `food_feeding.png`（多虫实景）、`food_stop_ring.png`（小/中/大单虫对照）。

## 交配动作与视觉

原来交配只有 tremor=0.45 抖动 + 一个暗色黏液点，等于"两只虫贴着不动"。
新增 `src/animation/mating.py`（MatingRig），拆成动作 + 样式两层。

**动作**（全部由 u=progress/duration 直接算，不积累状态）：
- `phase_at(u,dur)` = 2π·dur·(F0·u + F1·(b-a)(t³-t⁴/2))，freq 1.6→4.8Hz；
  **必须解析积分**，否则用 sin(2π·freq(u)·t) 在变速点会跳拍（抽搐）。
- push = 4.2px·env·sin（体长 6%；2.2px 截图里 8 帧像同一张）
- twist = 1.8°·env·cos，**绕尾端**转（尾部是锁合点，绕体心转像被拨了一下）
- squeeze = ±3.2%（雌 2%），只缩放躯干，六足不拉（拉了像橡皮虫）
- 包络：前 10% 涨起、后 12% 落回，并**额外后退 9px**（抽离；只落回 0 会像卡带）
- 位移只改 painter.translate，**不动 self.pos**（否则配对距离/点击命中全错）

**样式**：预渲染光晕贴图（随拍呼吸+明暗）、每拍一圈波纹（age=frac(phase/2π)）、
每拍一颗心形（两段三次贝塞尔预渲染，不用字符 ♥ —— 离屏字体数为 0 会变方框）。
三条硬约束：只画雄虫（两头画会叠成过曝）；心形用**世界坐标**（雄性转 180° 后局部 -y
是屏幕下方，会往自己身体里飘）；心形单独一遍画在所有虫体之后（否则被伴侣挡住）。

**踩坑**：`tools/mating_preview.py` 第一版存 (progress, female, male) 引用，
8 帧全是模拟结束后的同一状态 —— 看起来像 8 张静帧，其实是 1 张画 8 遍。
改成逐帧 `capture()` 成 QImage。

**调参过程**：光晕半径 0.68→0.36 body_len（大了像粉色气球/玫瑰花瓣色带，
渐变要 7 段才不 banding）；中心色不能太白（浅色桌面上像白雾）；分泌物高光取消
（深底上会变成发亮"胶囊"）；圆环 8+38·age → 6+22·age。

**验收**：reproduction_test 30→45（新增 [11]：相位单调/末段加速、包络、挺动幅度、
抽离、心形上限与清空、两帧必不同、开销预算）；others 全过。
开销：一对 0.93ms/帧（WALK 0.81，特效 ≈0.12ms）。悬停卡片改「交尾中 · 62%」。

## macOS 适配落地（承接上一条的 5 项，全部做完）
- 新增 `src/utils/objc_bridge.py`：纯 ctypes 的 objc_msgSend 胶水。**每种签名
  必须单独 cast**（`_fn(restype, argtypes)` 按 (类型,参数) 缓存 CFUNCTYPE），
  用通用 c_void_p 调会读垃圾寄存器 / arm64 截断指针。
- `mac_hotkeys.py`：Carbon `RegisterEventHotKey` + 在 ApplicationEventTarget 上装
  handler，靠 `GetEventParameter(kEventParamDirectObject/typeEventHotKeyID)` 取回 id。
  不需要辅助功能授权（这是选它而不是 addGlobalMonitor/CGEventTap 的唯一理由）。
  修饰键另一套位（cmd 0x100/shift 0x200/opt 0x800/ctrl 0x1000），键码 `kVK_*`
  按**键名**从 `key_label(vk)` 再查。
- `mac_hit_test.py`：`ignoresMouseEvents` 每帧开关 + `QCursor.pos()` 判点，
  复用同一个 `accepts_mouse_at()`。**不用 setMask 兜底**：mac 上 setMask 语义不保证
  裁输入，而"持拍整屏接管"一旦不成立就是整块桌面点不动。
- `mac_occlusion.py`：`CGWindowListCopyWindowInfo` 返回前→后顺序，走到自己面板窗口
  就停，靠 `ownerPID` 滤掉覆盖层（它在第 1000 层，否则永远判"被挡"）。

  首次运行从包内 config.toml **播种**到可写位置，不是用 DEFAULT_CONFIG 重写。
