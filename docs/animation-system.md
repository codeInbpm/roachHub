# 蟑螂肢体动画系统

> 目标：让蟑螂的触须与六足在游走、受惊、梳理、交配等状态下**连续自然地动起来**，
> 且动作与移动速度真实耦合，不再是「一张图整体旋转」。

---

## 一、原来的问题

改动前 `Cockroach.render()` 的流程是：`drawPixmap(整张贴图) + 两条 quadTo 触须`。
实测下来有四个硬伤：

| 现象 | 根因 |
| --- | --- |
| 六足完全静止，只能整体转向 | 腿和触须被烘焙在照片里，贴图只有一张，没有可驱动的结构 |
| 看起来有「四根触须」 | 照片自带两根触须，代码又在其上叠加了两条矢量触须 |
| 体态偏瘦长、像甲虫 | 313×319 的贴图被塞进 62.7×118.8 的矩形，纵向被拉伸约 1.85 倍 |
| 腿间有白色/灰色补丁 | 原始抠图只做了四边漫水填充，腿与躯干围出的封闭浅色区域没被抠掉 |

结论：**不是缺帧，而是缺结构**。补几十张序列图能解决"动"，但解决不了
"动作随速度变化""状态之间平滑过渡"，而且素材量与维护成本都会失控。

---

## 二、方案取舍：程序化骨架 vs 预渲染序列帧

| | 程序化骨架（本次采用） | 预渲染序列帧 |
| --- | --- | --- |
| 动作量 | 任意速度/任意状态自动生成 | 每个状态 × 每个速度段都要单独一套 |
| 连贯性 | 由相位连续推进，帧间天然连续 | 取决于帧数，帧数不够会「跳」 |
| 素材成本 | 3 张躯干图（各 ~120×215） | 至少 6 状态 × 12 帧 × 3 体型 ≈ 200+ 张 |
| 状态过渡 | 参数插值，可平滑混合 | 需要额外的过渡帧或淡入淡出 |
| 适用场景 | 运行时实时渲染（本项目 60 FPS 的 QPainter 覆盖层） | 固定机位、固定动作的影视/游戏序列 |

所以这里做的是**「由速度驱动的程序化骨架」**：步态相位 → 足端轨迹 → 两段式 IK
→ 锥形肢体绘制。它比序列帧更连续，也更省资源。

---

## 三、结构

```
assets/sprites/*_body.png        由照片拆出的「纯躯干」贴图（腿/触须已切除）
        │
src/animation/
  pose.py      PoseBlender        15 个姿态参数各自指数平滑，负责状态间连续过渡
  gait.py      LegRig             六足：三足步态相位 → 足端轨迹 → 两段式 IK → 绘制
  antennae.py  AntennaRig         触须：多段链 + 行波 + 带滞后的朝向追随
        │
src/entities/cockroach.py
  update()  状态 → 姿态目标 → 平滑 → 骨架推进 → 触须推进
  render()  阴影 → 六足 → 躯干贴图 → 触须 → 交配特效
```

绘制顺序按俯视遮挡关系排：腿在躯干**之下**（基节被体缘压住），触须在躯干**之上**。

## 四、步态模型

### 4.1 交替三足步态

蟑螂用三角步态：**左前 / 右中 / 左后** 为一组同时着地，另外三条同时抬摆，
两组相位差半个周期。任何时刻都有三条腿撑地，因此身体不会"翻倒"。

```python
PHASE = {(-1,0):0.0, (-1,1):0.5, (-1,2):0.0,
         ( 1,0):0.5, ( 1,1):0.0, ( 1,2):0.5}   # (side, 足序号) -> 相位偏移
```

### 4.2 支撑相 / 摆动相

单腿在一个周期内：`p < duty`（默认 0.62）为支撑相，其余为摆动相。

- **支撑相**：脚掌钉在地面。身体向前走，所以在**体坐标系**里脚是向后平移的，
  位移 `-stride/2 → +stride/2`。这是"不滑步"的关键。
- **摆动相**：抬腿前摆，位移 `+stride/2 → -stride/2`，并用 `sin(πu)` 做抬腿弧线。
  俯视投影下"抬高"表现为脚端向髋部收拢（透视缩短），所以抬腿是可见的。

步幅不是常数，而是 `stride = 速度 / 步频`：走得快 → 步幅大、步频高；走得慢 → 反之；
停下时相位停止推进，不会"原地踏步"。

### 4.3 两段式 IK

给定髋点 H 与足端 F，用余弦定理求膝点，取"向体外侧弯折"的那一组解
（俯视图里膝点是腿的最外点，符合昆虫解剖）：

```python
a = acos((l1² + d² - l2²) / (2·l1·d))
knee = H + l1 · dir(angle(H→F) ± a)      # 取外侧解
```

足端位置本身再做一次指数平滑（τ=0.045s），所以状态切换、转向时足端不会瞬移。

### 4.4 身体次级运动

- 横向摆动 `body_sway`、偏航 `body_yaw`：频率 = 步态周期，幅度 ∝ 步幅；
- 起伏 `body_bob`：2 倍频（每落地一组三足起伏一次）；
- 惊慌时步频、步幅、外展角同时变大，躯干另加高频抖动。

## 五、触须模型

触须是 7 段链，每段角度 = 基础朝向 + 累积弯曲 + 行波：

```python
wave_i = amp · ((i+1)/n)^1.35 · sin(phase − i·0.85)
```

`(i+1)/n` 的幂次让摆幅从根部到梢部递增 —— 根部稳、梢部活，这是鞭状触须的关键；
`− i·0.85` 的相位延迟让波从基部传向尖端，而不是整根同步摆动。

整根触须的朝向由一个 τ=0.085s 的滞后追随驱动：

- **常态**：指向前方 ± 张开角，叠加两个不同频率的正弦做缓慢扫探；
- **警觉**：按警觉度权重转向 `threat_vector`（体坐标下的威胁方位）；
- **受惊/交配**：向后伏倒，频率升到 13~26 Hz；
- **梳理**：被梳理一侧的触须下弯到前足之间（弯曲量加倍）。

## 六、状态 → 姿态映射

`STATE_POSES` 把行为状态翻译成姿态目标，`PoseBlender` 用不同时间常数平滑过去
（惊吓 0.07s 快切，梳理 0.14s 缓入）：

| 状态 | 步幅 | 外展 | 锚定 | 颤抖 | 梳理 | 触须 |
| --- | --- | --- | --- | --- | --- | --- |
| IDLE | 0.15 | 0.30 | 0.92 | – | – | 低频扫探 4.2Hz |
| WALK | 1.0 | 0.36 | 0 | – | – | 7.6Hz |
| PANIC | 1.65 | 0.52 | 0 | 0.18 | – | 后伏 22Hz |
| FREEZE | 0 | 1.0 | 1.0 | 0.05 | – | 后伏 26Hz |
| GROOMING | 0 | 0.22 | 1.0 | – | 1.0 | 同侧下弯 |
| EAT | 0 | 0.26 | 1.0 | 0.02 | 抱食 1.0 | 6Hz，前伸搭在食物上 |
| DRAGGED | 0.9 | 0.85 | 0 | 0.50 | – | 各自狂扫 30Hz |
| MOLTING | 0 | 0.75 | 1.0 | 0.12 | – | 5Hz |
| MATING | 0 | 0.48 | 1.0 | 0.45 | – | 后伏 13Hz |
| DEAD | 0 | 0 | 1.0 | – | – | 蜷缩 |

"锚定"（anchored）是步态权重：为 1 时脚掌钉住不动，只保留静止微调步
（tarsal adjustment：偶尔抬起一只脚换个落点，避免静止时像标本）。

另有三个通道不属于上表：`flail`（被捏在空中时原地蹬腿，允许脚不落地也推进步态相位）、
`hold`（前足抱食）、`probe`（静止探嗅时身体前倾 1.5px）。它们由交互层驱动，
详见 [`interactions.md`](interactions.md)。

> 注意：以上全部依赖主循环每帧调用 `entity.update(dt)`。该调用曾长期缺失，
> 导致动画在真实运行中完全不推进（详见 `interactions.md` 第 0 节）。

## 七、贴图拆分管线

`tools/build_body_sprites.py` 把照片拆成纯躯干图，纯 Qt 实现（不引入 numpy/PIL）：

1. **转正**：若虫/蜕壳贴图是 3/4 侧视斜角，先旋转到"头朝上"（成虫 0°、若虫 103°、蜕壳 117°）；
2. **轮廓蒙版**：用参数化躯干轮廓（头/前胸背板/翅/腹的宽度分布）切掉六足与触须，
   轮廓在三个"足基带"处特意收窄，让残留的足基尽量被切掉；
3. **背景洪泛**：从画布四边出发，穿过「轮廓外」或「近白高光背景」的像素。
   躯干内部的高光被虫体像素围住，洪泛到不了 —— 于是白色补丁被清掉、高光被保留；
4. **去残茬**：逐列检查纵向连续长度，清掉明显短于躯干厚度的碎段（残余足基）；
5. 输出 `*_body.png` + `*_body.json`（含旋转角、包围盒、长宽比）。

运行时 `Cockroach._setup_rig()` 直接读躯干图长宽比来决定体长/体宽，
因此骨架尺寸与照片躯干天然一致，不需要手填数字。

重新生成：

```bash
QT_QPA_PLATFORM=offscreen python tools/build_body_sprites.py
```

## 八、性能与 LOD

肢体是逐帧计算的，同屏数量大时需要降级。`Cockroach.quality` 由主循环按数量动态设置：

| 同屏数量 | 档位 | 处理 |
| --- | --- | --- |
| ≤ 55 | 2 精细 | 锥形肢体 + 关节 + 刺毛 + 平滑缩放 |
| 56–110 | 1 标准 | 去掉刺毛，触须隔点取样 |
| > 110 | 0 极简 | 六足合并为单条路径描边、无阴影 |

离屏实测（1600×900，含 `update` + `render`，Windows / PySide6 6.12 / CPU 渲染）：

| 数量 | LOD2 | LOD1 | LOD0 |
| --- | --- | --- | --- |
| 10 只 | 4.0 ms | 3.7 ms | 2.2 ms |
| 50 只 | 18.7 ms | 18.6 ms | 11.0 ms |
| 150 只 | 56~64 ms | 55 ms | 31 ms |

日常种群（3~30 只）稳定在 60 FPS；150 只是配置上限的极端情况，会降到 30~40 FPS。
若需要极限密度也满帧，下一步应把腿部光栅化改成 QSG 场景图或预烘焙 8 方向腿部贴图。

## 十、已知限制

1. **若虫与蜕壳贴图是 3/4 侧视**，转正后仍带一点斜角，套用俯视骨架时腿部角度
   不会完全贴合。游戏中若虫体长仅 20~55 px，实际不可辨；若追求一致，应重拍俯视素材。
2. **躯干侧缘仍有少量足基残茬**（照片里足基与体缘相接，几何上无法完全切净），
   已用基节圆点覆盖大部分；近看可见 2~3 px 的浅色凸起。
3. **足端没有真实的地面接触物理**：支撑相是"体坐标系里匀速后移"的等效处理，
   不是逐帧求解地面约束；因此在急转弯的瞬间可能出现极轻微的滑步。
4. 躯干贴图被拉伸到 1.84:1（原照片 1.72:1），保留了少量纵向拉伸以更接近蟑螂体态，
   不是纯粹的等比缩放。
