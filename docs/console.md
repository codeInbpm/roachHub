# 控制台、全局热键与「虫巢爆发」

> 三个诉求：**① 启动就打开控制台 ② 像微信那样用快捷键收起/召唤 ③ 能一键刷满屏、能批量放虫**。
> 本文记录它们怎么实现、为什么这么做、以及哪些地方做了取舍。

---

## 1. 三个入口，一套语义

| 入口 | 行为 |
| --- | --- |
| 启动 | 默认直接弹出控制台（`app.open_console_on_start = true`，可在「⌨️ 快捷键」里关掉） |
| 托盘**单击** | **召唤**控制台（先还原最小化 → show → raise → activateWindow）；右键出菜单；双击不再绑定其它动作 |
| `Ctrl+Alt+R` | 显示 / 隐藏控制台（全局热键，应用没有焦点也生效） |
| 重复启动 `main.py` | 不再叠第二个实例，而是把已在运行的那个控制台叫出来 |

**托盘单击为什么是"召唤"而不是"开关"**：用户点托盘时想要的永远是"把面板拿来"。
如果做成取反，面板被别的窗口挡住（或最小化成一条）的时候点一下只会把它再藏一次 ——
表现就是**点了没反应**。所以托盘走 `summon_console()`（幂等），只有热键和菜单里的
「隐藏」才真的收起。

`summon_console()` → `open_settings()` 是托盘/菜单/启动共用的路径；`toggle_console()`
只给热键用，它用 `console_in_front()`（可见 **且** 没被别的窗口压住）判断"该收还是该叫"：
被压住时按热键是**召唤**，不是藏起来。两条路径都先处理"可见但最小化"：`show()` 对最小化
窗口是无操作，不显式 `setWindowState(... & ~WindowMinimized)` 就永远叫不出来。

**为什么"启动即打开"要跟 `start_hidden` 分开**：`start_hidden` 管的是**桌面蟑螂覆盖层**，
`open_console_on_start` 管的是**控制台窗口**。两者正交 —— "启动时先别让虫子上桌，但我要调参数"
和"上来就让虫子爬满屏，不要面板"都是合理诉求。

**只在"重新弹出"时回读配置**：控制台开着的时候再点托盘不会 `load_from_config()`，
否则用户填了一半的参数会被抹掉。

## 2. 全局热键为什么必须自己做

Qt 没有全局热键 API。`QShortcut` / `QAction.setShortcut` 只在**本应用有焦点**时收得到键，
而桌面宠物的核心场景恰恰是"用户正在用别的软件，想顺手把面板叫出来"。所以只能走 Win32
`RegisterHotKey`（`src/utils/hotkeys.py`）。

**两个坑（都踩过）**

1. `RegisterHotKey(None, ...)` 把热键注册到**当前线程**，`WM_HOTKEY` 投递到线程消息队列，
   Qt 会以 `windows_dispatcher_MSG` 交给 native event filter。只判断 `windows_generic_MSG`
   会永远收不到 —— 两种都收。
2. 热键是**系统独占**的。被别的程序占了（或本进程重复注册同一组合），`RegisterHotKey` 返回 0，
   `GetLastError()` = 1409。必须把失败原因暴露给用户。

**默认键为什么不是 `Ctrl+Alt+W`**：这台机器上它已被占用（很可能是微信自己），
实测一注册就 1409。默认改成同族的 `R`（console）/ `H`（hide）/ `B`（burst），
并在控制台里实时标出「已生效 / 未生效：已被其他程序占用」，**不让用户以为设了却没反应**。

**录制热键时不能真的触发**：用户点开"显示/隐藏控制台"的录入框、按下当前那个组合键，
`toggle_console` 会当场把窗口藏起来 —— 录音时不能把自己静音。`app._guarded()` 在
"设置窗是活动窗口 **且** 焦点在 `QKeySequenceEdit` 上"时直接丢弃这次热键，其余情况照常执行。

**至少一个修饰键**：裸字母（如只写 `W`）注册成全局热键会吃掉系统里每一次 W，解析阶段直接拒绝。
空串 = 禁用该热键（`RegisterHotKey` 不注册，但配置里保留空值）。

## 3. ⚡ 虫巢爆发

**语义：补满，不是重置。** 已经养了 50 只，用户要的是"再来一波"，不是"把现有的清掉重来"。

```
room = min(max_roaches, BURST_HARD_LIMIT) - 当前存活
补 room 只（混合：约 1/3 若虫、其余成虫，雌雄按配置比例）
以屏幕中心为惊源，让全场 trigger_freeze_and_panic() → 瞬间僵直 0.1s，然后四散
音效只响一次（rustle），不是 200 次
```

- 已达上限时返回 0，**但仍然会炸一次** —— "爆发"该有的观感不能因为满员就消失；
- `BURST_HARD_LIMIT = 400`：防止用户把 `max_roaches` 误设成 9999 时一键把机器打死；
- 新生个体不逐个进 PANIC，而是统一走 `_burst_panic()`，保证"整巢同时炸开"而不是"边生成边炸"。

## 4. 批量投放

**为什么不直接循环调 `spawn_cockroach()`**：那条路径每只都打一条 INFO 日志、刷新托盘 tooltip。
一次 150 只 = 150 行日志 + 150 次 `NOTIFYICON_MODIFY`（单次 5~30ms）。所以 `spawn_batch()`
走 `announce=False`，只在最后统一刷新一次托盘统计。

| 行为 | 说明 |
| --- | --- |
| 容量截断 | 请求 999 只、只剩 150 空间 → 放 150，日志写「请求 999，剩余容量 150」 |
| 阶段 | 混合（1/3 若虫，若虫龄期随机分布）/ 全成虫 / 全若虫 |
| 入口 | 控制台「批量投放蟑螂」+ 快投 `+10 / +50 / +100`；托盘子菜单 一只/十只/五十只/一百只 |
| 食物 | 控制台一次 N 块；托盘 一块/十块 |

**性能**：200 只全新建构 ≈ 15ms（贴图有 `ResourceManager` 缓存，重复构造不重新解码）。
放完后 `_on_tick` 的 LOD 预判（>110 → LOD0）会在下一帧把画质降下来，不需要额外处理。

## 5. 控制台是哪一页

启动默认停在 **0 号页「🪳 控制台」**：

- 当前群落：`画面内 N / 上限` 进度条 + 成虫 ♀/♂ · 若虫 · 卵鞘 · 碎屑 + 画质 LOD 与帧率上限；
- ⚡ 虫巢爆发；批量投放蟑螂（数量 + 阶段 + 快投）；批量投放食物；驱散所有；隐藏/显示桌面蟑螂。

这一页全是**即时动作**，点了就生效，不需要「保存并应用」；底部用一行 toast 反馈（4 秒后自动清空），
不弹模态框打断。状态区由 500ms 定时器刷新，窗口不可见时自动跳过；
`showEvent` 里也立刻刷一次，别让用户对着"0/0 只"等半秒。

**保存后不再关窗**：控制台是长期开着的面板，不是一次性对话框。保存成功 → 底部提示「已保存并即时生效」；
只有"热键没注册上"这种需要用户决策的情况才弹窗，并列出到底哪个键失败、为什么。

7 个页签在 880px 宽度下能全部平铺，不会退化成滚动箭头（曾因为 700px 挤出 `◀ ▶` 按钮）。

## 6. 打开控制台会让自适应器误判

创建窗口 + 首次布局会卡住消息循环上百毫秒。实测启动日志里出现过
`帧耗时 48.7ms 超过底线 → 画质降到 LOD1`，两秒后又恢复 —— 典型的**一次性抖动污染 EMA**。

修法：`reset_frame_governor()` 在 open_settings() / 应用配置后把 `_frame_ema` 归位到预算值、
清零连击计数、并把 `_last_tick_time` 重置为当前时刻（否则下一帧的 `raw_ms` 会把窗口构建时间算进去）。

## 7. 全屏覆盖层不能"吃掉"桌面、任务栏和控制台

**症状**：用户点右下角托盘图标没反应，"整块右下角好像卡住了，什么都点不了"。

**不是托盘坏了，是点击被覆盖层抢走了。** 覆盖层是 2560×1440 全屏置顶，**连任务栏一起盖住**。
没画东西的地方 alpha=0，Windows 会自行跳过；但**只要有蟑螂趴在那个像素上**，
`WM_NCHITTEST` 就会问我们"这个点归谁"，而我们的回答是"归我"——于是托盘图标收不到点击。

用 `WindowFromPoint` 一测就清楚了（它内部就走真正的命中测试）：

| 位置 | 修复前 | 修复后 |
| --- | --- | --- |
| 空桌面 | `XZDesktopWnd` | 不变 |
| 托盘（空） | `TrayNotifyWnd` | 不变 |
| 托盘 + 1 只蟑螂 | **覆盖层** ← 点击被吃掉 | `TrayNotifyWnd` |
| 控制台面板 + 1 只蟑螂 | **覆盖层** ← 按钮点不动 | 控制台窗口 |

**修法：覆盖层主动"让位"两块地**（`src/overlay_window.py`）

1. **任务栏死区**：`resize_to_screen()` 记下 `screen.availableGeometry()`（工作区）。
   `hit_test_at()` 里第一件事就是"这个点不在工作区 → 一律不认"。
   蟑螂照样能爬到任务栏上（观感不变），只是那里**不再接管鼠标**；
2. **控制台洞口**：控制台 `move/resize/show/hide/激活` 时发 `geometry_changed`，
   `app._sync_console_hole()` 把 `frameGeometry` 换算成覆盖层坐标 + 4px 余量，
   调 `overlay.set_hole_region()`。覆盖层做两件事：
   - `paintEvent` 里 `setClipRegion(整屏 - 洞)` → **蟑螂走到面板边缘就"钻到下面去"**，不盖字；
   - `hit_test_at` 里洞口一律返回 `None` → 按钮/输入框的点击直达面板。

### 7.1 洞必须跟着 z-order 走（否则会出现"虫子走进去就消失"）

**症状**：满屏蟑螂，屏幕中间有一块矩形，**虫子跑进去就凭空消失**，走出来又出现。
而那块矩形恰好是控制台面板的尺寸 —— 但屏幕上根本看不到面板。

**原因**：洞是按 `frameGeometry` 挖的，只跟面板的**位置**有关，跟它**有没有露在最前面**无关。
控制台是普通窗口，用户点一下浏览器 maximized 就把面板压到后面去了。面板被挡住了，
洞却还留在原地 —— 用户能看到的就只剩那个洞。

**修法**：洞 = 面板矩形 **−** 压在它上面的窗口矩形（`src/utils/win_occlusion.py`）。

- 用 `GetTopWindow` / `GW_HWNDNEXT` 从 z-order 最顶层往下走，**走到面板句柄就停**
  （它下面的窗口不可能挡住它）；
- 只统计**可见、未最小化、不是本进程**的窗口（本进程的覆盖层自己是 topmost，必须跳过，
  否则它永远"挡住"自己）；
- 跳过 `WS_EX_TRANSPARENT`（点击穿透的 HUD）和 `WS_EX_NOACTIVATE`（输入法候选框之类）；
- 完全被挡住 → 洞为空 → 整屏归蟑螂；**被挡住一部分** → 只挖露出来的那部分。

触发时机：面板 `ActivationChange` / `WindowStateChange`（即时）+ 250ms 轮询（兜底）。

顺带修了同一根源的另一个坑：**"可见但被压住"时按 `Ctrl+Alt+R` 会把面板藏起来**。
用户按热键的意图是"把面板叫出来"，所以 `toggle_console()` 现在用
`console_in_front()`（可见 **且** 没被压住）判断 —— 压着就召唤到前台，真的看得见才收起。

选"挖洞"而不是"把控制台设成置顶"：两个 topmost 窗口谁在上取决于谁最后被激活，
用户点一下桌面上的虫子，覆盖层就可能又翻到面板上面去了。**挖洞与 z-order 无关**，永远成立。

顺带把 `_clip_region` 预先算好（整屏减去洞，只有 5 个矩形），每帧只调一次 `setClipRegion`，
**不是**每帧重建窗口形状 —— 后者正是之前"屏幕闪烁"的根因。

**另一个"点了没反应"的来源**：同时开两个 `main.py`。两个一模一样的托盘图标、两个全屏覆盖层，
点到的可能是旧实例的，谁吃点击还取决于谁在上层。所以加了单实例守卫（`src/utils/single_instance.py`）：
`QLockFile`（存 PID，能识别崩溃残留）+ 命名管道唤醒，第二次启动 290ms 内退出并叫醒第一个。

> 注意**不能**拿 `QLocalServer.listen()` 的成败当占有标志：Windows 上同名管道允许同时监听，
> 实测第二个进程 `listen()` 依然返回成功，那样守卫等于没做。

- 启动 → 控制台可见；合成 `Ctrl+Alt+R` → 隐藏；再按 → 显示（三次真实按键，全部符合预期）；

## 9. 已知限制

1. **面板洞里的蟑螂抓不到**：蟑螂会走到面板背后（那里不画、不接管鼠标），此时既看不见也抓不着，
   挪开面板或等它走出来即可。这是"按钮必须点得动"的必要代价。
2. **任务栏上的蟑螂抓不到**：同理，任务栏那一带永远让给系统。
3. **热键冲突只能提示不能强占**：系统独占，被占用就必须换组合。控制台会告诉你是哪个键、为什么。
4. **`Ctrl+Alt+B` 是全局的**：在别的软件里按到也会放虫。这是"一键刷满"的代价；不想要就留空禁用。
5. 爆发上限硬编码 400（`RoachApp.BURST_HARD_LIMIT`），即使把「生物上限」填成 999，
   一次爆发也只放到 400 —— 4K 屏上 400 只大约 15~20 FPS，再高就真的不流畅了。
