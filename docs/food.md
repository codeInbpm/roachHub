# 食物体系（恶心版）、腐败规则与状态卡片

这份文档解释五件事：桌面上能出现哪些**脏东西**、食物为什么会长霉爬蛆、贴图怎么做到"高保真但不吃内存/CPU"、虫到底**停在食物的哪个位置**啃，以及"鼠标停在虫身上才显示状态"的实现。

---

## 1. 为什么要换掉那一桌"饼干渣"

第一版是 20 种精致食物：面包屑、蜂蜜滴、奶酪三角、月饼渣、蛋糕……造型都挺好看。

问题是**方向错了**。桌面蟑螂模拟器里，撒一地把蛋糕屑和蜂蜜滴看起来像"下午茶摆盘"，
而不是"这屋里该打扫了"。用户的原话是"太美观了，我要的是恶心的效果"。

现在的清单是**腐肉、蛆团、死毛毛虫、老鼠屎、发霉面包、烂番茄、霉奶酪、死苍蝇、
死蛾子、死蜘蛛、死马陆、死蛞蝓、死跳蚤、死鼠妇、蟑螂若虫尸、霉斑……**

这同时解决了一个玩法问题：投喂不再只是"加能量"，而是"你愿意在桌面上放什么"。

## 3. 高保真贴图，但不吃内存也不吃 CPU

### 3.1 为什么不用代码画

程序化 `QPainterPath` 画不出"一条长着体节的蛆"。第一版 15 种 `shape` 的顶点是手调的，
最好也就是"一眼认出是个碎块"。

所以改成 **AI 生成的微距照片素材 + 离线抠图 + 运行时贴图**：5 张 1024×1024 的 2×2 素材图，
切成 23 张 256×256 的透明 PNG（`assets/sprites/food/`），再由 `tools/prepare_food_sprites.py`
额外烘三档腐蚀染色，一共 24 组、约 6.3 MB **磁盘**。

### 3.2 抠图踩过的坑（都写在脚本注释里）

素材是"纯白背景 + 柔光落影"的摄影棚风格，直接贴到桌面上会露馅。四版才收敛：

| 问题 | 现象 | 修法 |
|---|---|---|
| 亮度阈值一刀切 | 落影留成**实心灰块**、白底过渡带留成**一圈白雾** | 改成从边界泛洪的连通域，只吃与边界连通的近白像素 |
| 边缘半透明像素 | 浅色桌面上出现**一圈灰白光晕**，像贴纸 | 离背景 1~2 圈的像素直接透明，第 3 圈压到 alpha 36 并压暗 |
| 落影是"灰"不是"影" | 桌面上一圈灰雾 | 低饱和高亮像素压成 alpha 38 的深灰，才像投影 |
| 取景框按"所有不透明像素" | 周围几粒碎屑把框撑大一倍，主体只占画布 56%，**又小又淡** | 只认**面积最大的连通块**，外扩 6% |

第三条尤其关键：外扩从 18% 收到 6% 之后，主体在 256 画布上的占比从 67% 提到 90%，
同样的 `radius` 下视觉尺寸直接大了一圈。

### 3.3 内存：惰性 + 只留最终尺寸

`src/entities/food_sprites.py`：

- **解码一次就丢原图**：256×256 的 PNG 读进来，立刻缩放到"该种类最大显示尺寸 × DPR × 1.7"
  （超采样，保证缩放后边缘不糊），原 `QPixmap` 不进缓存；
- **缓存键是 `(sprite, 像素尺寸)`**：一个种类通常只有一条；
- **惰性**：没投放到桌面上的种类一张都不读盘；读失败记进 `_MISSING`，不每帧重试。

实测（`food_test.py` 的断言）：

```
23 种全渲一遍后  46 条缓存 / 508,664 px / 1986 KB
```

约 2 MB。注意这是**把 23 种全部渲染过一遍**的上限；实际同时出现在桌面上的种类通常只有
3~6 种，真实占用 300~600 KB。作为对比，一张 1080p 壁纸解压后就是 8 MB。

### 3.4 CPU：把静态的东西全部烘掉

第一版把"菌斑"也放在运行时画：每片菌斑 3 个椭圆、15 片、3 条蛆每条 8 个椭圆。
12 块烂透的食物 **4.04 ms/帧**，吃掉 60fps 预算的四分之一。

改法两条：

1. **菌斑完全烘焙进 `_d1/_d2/_d3` 三档贴图**（离线用 `SourceAtop` 只画在不透明区域，
   不会糊成一圈绿边）。运行时不再重画。
2. **蛆改成预渲染的 32×32 小图**（5 节递减 + 背脊高光 + 头部暗点），模块级缓存一张，
   扭动靠每帧改旋转角。从"每条 8 次 drawEllipse"变成"每条 1 次 drawPixmap"。

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 12 块（混合新鲜度） | 1.54 ms/帧 | **0.94 ms/帧** |
| 12 块全新鲜 | 0.80 ms/帧 | **0.82 ms/帧** |
| 12 块全烂透 | 4.04 ms/帧 | **1.53 ms/帧** |

顺带一提，换成贴图之后"造型"这件事也消失了：`FoodKind` 不再需要 `shape` 字段，
新增一种食物 = 加一行数据 + 一张 PNG。

## 4. 腐败规则

### 4.1 一条食物的一生

```
新鲜 ──── 48% ──── 开始长霉 ──── 26% ──── 爬蛆 ──── 18% ──── 渗水 ──── 烂光消失
 │                                                                      │
 └─ freshness 1.0 ────────────────────────────────────────→ 0.0 ────────┘
```

| 阶段 | `rot`（=1−freshness） | 表现 |
|---|---|---|
| 新鲜 | 0 ~ 0.28 | 原图 |
| 发霉 | > 0.28 | 换 `_d1` 贴图：整体压暗一档 + 3 片菌斑 |
| 长蛆 | > 0.55 | 换 `_d2`：更暗 + 9 片菌斑；边缘探出白色小蛆（1~3 条，会扭） |
| 渗水 | > 0.72 | 换 `_d3`：焦黑 + 18 片菌斑；底部淌下 3 道暗色液痕 |
| 烂光 | = 1.0 | `is_alive=False`，`death_reason="rotted"` |

两种食物有例外：`maggots`（蛆团）的 `grub_min_rot = 0.0` —— 它**从投放那一刻起就有蛆在爬**，
否则新鲜状态下它就是一块安静的白色脂肪，完全不像名字。

### 4.2 数值

```python
# 每帧
speed  = 1.0 + (被啃掉的比例) * 0.9      # 被啃过的坏得更快，最多 1.9 倍
age   += dt * speed                      # 基类已经加过一次 dt，这里只补加速那截
fresh  = 1.0 - age / shelf_life
营养   -= max_nutrition * 0.45 / shelf_life * speed * dt   # 全程流失 45%
```

- **被啃过的更容易坏**：伤口暴露、汁水外溢，最多快 1.9 倍。
  这个加速用的是 `eaten_nutrition / max_nutrition`，**不是** `ratio` ——
  `ratio` 里还混着"腐败自己流失的营养"，会形成正反馈，让标称 100 秒的保质期
  实际 84 秒就结束（第一版就是这样，测试才抓出来）。
- **营养随腐败流失 45%**：微生物在吃这堆东西。视觉上体积随之收缩，和"被蟑螂啃"共用
  同一个 `ratio` 通道，所以腐烂的食物会一边变小一边变黑。
- **烂光即回收**：`freshness` 归零时直接移除，`death_reason = "rotted"`。

### 4.3 为什么必须有这条规则

上一版把"食物不再自己饿死"修好之后，副作用是**食物会一直留在桌上**：堆满 8 块上限后
就不再生成新的，桌面上摆着 8 块没人吃的碎屑，既不真实又浪费。

腐败同时解决三件事：自动回收、给食物加"时效"、让桌面越放越脏。

实测（真实主循环，300 秒）：

```
 30s 虫=  5 食物=3 均腐0.10 烂过半=0
 90s 虫= 13 食物=5 均腐0.26 烂过半=1
150s 虫= 21 食物=2 均腐0.29 烂过半=0
210s 虫= 29 食物=2 均腐0.88 烂过半=2
270s 虫= 35 食物=0 均腐0.00 烂过半=0
300s 虫= 31 食物=1 均腐0.00 烂过半=0
```

食物数量长期在 **0~5 块**之间流转（不再是"堆满 8 块"），平均腐败度会自然爬到 0.88 再归零。

## 5. 虫停在哪儿：进食位形

食物半径从 17（跳蚤）到 34.6（腐肉）差了整整一倍。旧代码里停靠距离是写死的：

```python
stop_dist = max(32.0, roach.body_len * 0.62)   # ≈43px，与食物大小完全无关
```

半径 7~15 的碎屑时代够用。换成照片贴图后，半径 34.6 的腐肉直径 69px，
虫却仍停在离中心 43px 处 —— 虫体（约 75px 长）整只压在食物上，
画面上看起来是"站在食物上"，而不是"在边上啃"。

现在按食物**实时半径**算停靠环：

```python
mouth = roach.body_len * 0.52 * roach.scale          # 体心 → 口器
ring  = max(26.0, mouth + food.visual_radius * 0.58)
```

- **0.70**：口器落在半径 70% 处 —— 头部前缘压在食物表面上，食物仍有 8 成露在外面。
  这是量出来的**视觉最优**：0.58 时头整个埋进食物，三只虫同吃会把 69px 的腐肉
  完全挡住（"食物不见了"）；0.80 时只剩天线尖碰一下，像在闻而不是在啃。
- `visual_radius = kind.radius * (0.45 + 0.55 * ratio)`：越吃越小，停靠环跟着收。
- **判定圈 5px**：从 66px/s 收速要滑 5px，框写 9px 时虫会停在环外一格，
  小食物（半径 17）的口器刚好悬空。

实测：腐肉（r=34.5）口器停在距中心 27.5px，跳蚤（r=17）停在 15.5px，
两者都落在食物表面内，且中心距相差 10.8px —— 虫确实"看食物大小决定站多远"。

食物被吃到最小时（`visual_radius` 只剩 0.45R）口器会离边缘约 0.25R，
但那一刻营养已归零、食物同帧消失，所以不需要让虫"跟着往前挪半步"
—— 那会让六足锚定的进食姿态出现滑步。

### 5.1 让位：三只虫不会叠成一坨

`eating_slots`（1~3）只限制**数量**，不限制**方位**。三只从同一侧走过来的虫
会停在同一个点上叠成一坨。所以每只虫进入两倍停靠环后，先挑一个空位方位角：

| 机制 | 做法 |
|---|---|
| 选角度 | `Food.open_slot_angle()`：从来向起转一圈取 24 个样本，选与已占方位夹角最大的 |
| 算"已占" | 已经在吃的（`Food.slot_angles`）+ 还在路上但预定了的（`_slot_reserve`） |
| 防抖 | 选定的角度钉在 `_slot_aim` 上逐帧复用；只在被别人占了（夹角 < 0.7 rad）时重选 |
| 退位 | 吃上 / 放弃目标时调 `_drop_aim()`，把预定方位让出来 |

每帧重算角度会随身体绕行抖动（"来向"一直在转），表现是原地左右摇摆 —— 所以必须钉住。

按食物分桶存预定（`_slot_reserve[food_id][roach_id]`），每次只扫这块食物的两三个人；
不这么写就是"每只虫扫全部虫"，200 只时是 O(n²)。

实测三只虫同吃一块蛆团：最近两虫间距 **14.5px → 73px**；
90 秒 40 只虫长跑，进食 84 次、吃光 43 块、零饿死，平均能量 92.4。

眼测图：`tools/out/food_stop_ring.png`（小/中/大三档单虫对照）、
`tools/out/food_feeding.png`（5 块食物 + 8 只虫的实景）。

## 6. 食物怎么决定种群上限

这是整份文档里最该记住的一节。

| 项 | 数值 |
|---|---|
| 食物生成 | 每 12 秒 1 块，桌面最多 8 块 |
| 单块营养 | 随机混合期望 40.2 |
| 供给速率 | ≈ 3.3 能量/秒 |
| 单只成虫代谢 | 0.6 能量/秒（静止 ×0.5，狂奔 ×3） |
| **可持续成虫数** | **≈ 5.6 只** |

`simulation.max_roaches`（默认 200）**不是真正的上限**。实测 720 秒只到 48 只，先冲高再回落，
饿死 87 只 / 老死 4 只。**峰值来自"出生红包"**：每只新个体出生时 `energy = 100`，
等于凭空注入 100 点能量。720 秒里新生约 87 只 = 8700 能量，而同期需求 10424、
供给只有 2440 —— 缺口正是靠这个红包填的。

推论：想让种群更大，**动食物供给（营养或间隔），不要动 `max_roaches`**。
如果哪天把"出生满能量"改掉，种群会立刻塌到 5~6 只。

## 7. 投放

| 入口 | 选项 |
|---|---|
| 控制台「批量投放食物」 | 数量 1~40 + 种类（随机混合 / 23 种按营养分三档分组）+ 说明行 |
| 托盘 `🪳 投放食物 ▸` | 7 种招牌 + 随机混合 ×1 / ×10 |
| 自动投放 | `simulation.food_kind`（默认 `random`），每 12s 一块 |

下拉框里的分组标题（`──── 高能 · 尸体与腐肉 ────`）在 UI 里被置灰不可选 ——
23 项平铺滚起来找不着东西。

招牌 7 种（`SIGNATURE_KEYS`）按"腐败快慢 / 营养高低"各取一个代表，让用户一眼能试到
腐肉（100s 就烂）和老鼠屎（380s 耐久）的差别。

`Food.kind_key` 记着它是哪一种，`Food.name` 是中文名，`Food.edible_note` 给一句
「还新鲜 / 开始发霉 / 长蛆了 / 烂透了」，日志与测试读这几个字段。

## 8. 悬停状态卡片

**默认不显示任何数字。** 桌面的前提是"这看起来就是桌面上有虫"，常驻 HUD 会直接破坏它。

触发条件（`OverlayWindow._refresh_hover`，每帧执行）：

1. 持拍时不显示（此时整屏归拍子）；
2. 用 `QCursor.pos()` 每帧重新做命中测试 —— **不能用 mouseMoveEvent 记下的位置**，
   蟑螂会自己跑开、鼠标不动时事件不再来，卡片会僵在原地；
3. 命中 `Cockroach` 时续期 0.30 秒，停手即收起；
4. 左键点过之后钉住 4 秒（点完立刻移开也能看清）。

```
成虫 ♀              可产卵 2
能量            34
[██████░░░░░░░░░░░░]
健康           100
[██████████████████]
偏饿 · 正在四处找吃的
```

| 能量 | 文案 | 颜色 |
|---|---|---|
| ≤ 0 且血 > 0 | 能量耗尽 · 正在掉血，约 0.7 秒后死亡 | 红 |
| ≤ 0 且血 = 0 | 已饿死 | 红 |
| < 20 | 饥饿 · 速度已下降，走不远了 | 橙 |
| < 40 | 偏饿 · 正在四处找吃的 | 琥珀 |
| ≥ 40 | 交尾中 / 被捏住了 / 受惊 / 进食中 / 蜕皮中 / 体力未恢复 / 状态良好 | 按状态 |

开销：200 只同屏时 `_refresh_hover` **0.048 ms/帧**。

## 9. 顺便修掉的三处代谢问题

### 8.1 食物会自己"饿死"

`NeedsSystem` 对所有 `is_alive` 实体一视同仁地调 `consume_energy`，而 `Food` 继承
`BaseEntity` 却没有重写它 —— 结果一块没人吃的食物在 **334 秒后**能量归零、每帧掉血、
自己 `die("starvation")`，而营养还剩 40。

修法：`BaseEntity.metabolizes = True` 作为默认，`Food` / `Ootheca` / `Exuvia` / `SquashedRoach`
置为 `False`。**只有真正有生理需求的个体才代谢。**

### 8.2 掉血速度跟着帧率变

```python
# 旧：每帧固定 -2.5，与 dt 无关
self.health = max(0.0, self.health - 2.5)
```

60fps 下是 150 血/秒，30fps 下只有 75 血/秒 —— **画质降档时虫反而死得更慢**。
改成 `STARVATION_DPS = 150.0` × `dt`，三种帧率实测都是 0.67 秒。

### 8.3 死因被丢掉

`die(reason)` 收下 reason 就丢，实体被清理时只剩一行「清理已死亡实体: ID=x」。
现在 `BaseEntity.death_reason` 会留下 `starvation` / `natural_lifespan` / `eaten_up` /
`rotted`，`EcologySystem` 的日志也带上类型与死因。

要统计死因分布，用 `tools/starve_probe.py`：

```bash
QT_QPA_PLATFORM=offscreen .venv/Scripts/python.exe tools/starve_probe.py --seconds 360 --sample 30
```

判读：**「需求/s」稳定高于「供给/s」就是在持续饿死**。

## 11. 已知取舍

- **浅色物体在白桌面上对比低**。蛆团、霉面包这类本身是米白的，放在纯白壁纸上不显眼。
  素材已经是"奶油色 + 暗色体节"能争取到的极限；深色壁纸上完全没问题。
- **菌斑位置同类相同**。菌斑烘进贴图，所以两块同种食物的霉点分布一样。
  实际上很难同时盯两块同种食物看，暂时不值得为它多存 23×N 张变体。
- **贴图不跟随桌面亮度**。贴图自带摄影棚落影，在极暗壁纸上会显得"浮"。
  `render` 里补了一层 alpha 14 的椭圆托底，再淡就看不见、再重就变灰盘子（试过 30/34，
  在白色桌面上直接是一圈灰圆盘）。
