## 1. 触须跟随光标「嗅探」

**原方案**：`threat_vector` 不设半径门槛、权重下限 0.15→0.3、双侧分离 ±0.22、
IDLE 探嗅微动作、35px 内先收触须再僵直。

**落地后的修正**

- 权重公式从"下限 + 警觉度"改成 **`0.30 + 0.70·prox + 0.25·alertness`**。
  原因：原来的 `_update_antennae_aim` 每帧都从"正前方"重新算，再用权重向威胁方向插值，
  本质是**一次性混合而不是持续跟随**。权重 0.6 时残留 40% 的"正前方"分量，
  光标在正后方时误差高达 65° —— 眼睛能看出来它"没在看你"。
  把 prox 在感知半径内拉到 0.85~1.0 后，误差降到 **13.5~18°**。
- `threat_proximity` 的映射改成**分段**：`dist ≤ r_far` 时 1.0→0.85，圈外 0.85→0
  线性衰减。避免"整屏任何风吹草动都让所有虫同时转头"的廉价感。
- 预警窗口统一 0.12s（原方案对 <35px 想用更短的 0.07s，实测会让"触须先缩"这一步
  只剩 4 帧，肉眼几乎看不出顺序）。

**验收**：绕行 5 个方位最大误差 13.5~18°（要求 <25°）；触须后伏出现在第 0~2 帧，
身体僵直在第 7~8 帧 —— 两者相差 ≥6 帧（0.1s），肉眼能看出"先收天线再定住"的顺序。

## 2. 足迹与油渍痕迹

**原方案**：落地事件 → 半分辨率图层 → 2~3 个 1.5~2.5px 的半透明点，alpha×0.996 衰减，
FIFO ≤4000 点，托盘清理入口。

**落地后的修正**

- 衰减不用"逐像素乘 0.996"，改成 **`DestinationOut` 全幅填充**（alpha = `1-exp(-dt/tau)`）。
  Qt 的合成器做这件事是硬件友好的，1920×1080 实测 **0.03ms/帧**（按 3.3Hz 摊薄后）；
  逐像素遍历在 Python 里是不可能的（>100ms）。
- 但这里踩了一个**量化陷阱**：8 位合成器按 `round(dst·(1-a/255))` 计算，逐帧衰减量只有
  ≈0.009（alpha≈2），乘出来小于 0.5 直接被舍回原值 —— 痕迹会永久卡在 alpha=11。
  解决办法是把逐帧衰减量**累加**，攒到 0.16（≈alpha 40）再统一填充一次。这也是"看起来
  完全没效果"却又不报错的典型症状。
- 放弃 FIFO 环形擦除：要精确擦掉最早的点，就得重绘受影响的区域并重新叠加所有相交的点，
  需要空间索引 —— 复杂度远超收益。改成**超限时淡出速度 ×4** + 长时间无新增时整层清空。
- 每个足印不是单个圆点，而是"一枚椭圆 + 两枚爪垫点"的微型图案，凑近看才分辨得出。
- 油渍的长轴要**沿前进方向**。第一版用了 `angle+90°`，结果每道油渍都垂直于行走方向，
  像一排横向的污点。

**验收**：3 秒 74~76 枚足印；16 秒后图层归零；1920×1080、约 2400 笔时淡出 0.03ms + 合成 0.45~0.65ms
≈ **0.5~0.7ms/帧**。
（有趣的反直觉结论：**1:1 原分辨率反而比半分辨率更快**——半分辨率的合成要多做一次双线性放大，
实测 0.5ms vs 0.83ms。所以只有 4K 屏才降到半分辨率。）

## 3. 抓取与挣扎

**原方案**：`DRAGGED` 状态 + 临界阻尼弹簧 + 六足乱蹬（`tremor=0.6, stride=0.8, anchored=0`）
+ 触须狂扫 + 松手 panic + 长按装死。

**落地后的修正**

- 原方案以为"`anchored=0` 就会蹬腿"，实际不会：`LegRig.update()` 里
  `moving = speed > 2.0 and anchored < 0.95`，被拎在空中时 `speed = 0`，步态相位根本不推进，
  六条腿会僵在原地。因此新增 **`flail` 姿态通道**，让"脚踩不到地但仍在原地蹬"成为可能。
- 影子必须跟着变：被拎起时影子位移 +7px、缩放 ×1.16、透明度 ×0.55。
  没有这一条，看起来像在桌面上滑动的贴纸。
- `MovementSystem` 必须**完全跳过** DRAGGED 实体（不是"减弱"）：趋边性、边界反弹、
  加速度积分任何一项参与都会和拖拽弹簧打架。
- 装死时长 6 秒、松手瘫软 0.9 秒，都是按"演示给人看"的节奏定的，不是生物学数据。

**验收**：拖拽跟随误差 9.1px；松手后 1s 内 390px/s；按住 6.6s 后 `dead=0.50, flail=0.00`。

## 4. 真实进食

**原方案**：`nutrition_left` + `shrink()`、EAT 姿态、每 0.4s 咬一口、`eating_slots=2`。

**落地后的修正**

- **停距**：第一版靠近到 20px 就开吃，而体长 70px —— 食物整个被躯干盖住，
  "食物在变小"这件事完全看不见。改成 `max(32, 0.62×体长)`，让头正好够到食物。
- 位点用 **2.5 秒心跳 TTL** 而不是集合。蟑螂被吓跑或死亡时不会走"正常释放"路径，
  用 TTL 兜底最简单，代价是位点最多被多占 2.5 秒。
- 食物被啃时不挖透明洞（`DestinationOut` 在覆盖层上可能变成黑块），改用暗色啃痕 + 体积收缩。
- 点食物不再触发惊吓（`Food.on_click` 改成只晃一下）。

**验收**：能量 40→75；营养比 1.00→0.00；食物消失。

## 5. 程序化窸窣音效

**原方案**：预生成 40ms 噪声样本、`QSoundEffect` 池化、落地事件驱动、音量按距离与数量衰减、
`Ctrl+Alt+M` 静音热键。

**落地后的修正**

- 样本在首次运行**用标准库现场合成**成 4 个 WAV（step / rustle / munch / thud）写到临时目录，
  不引入二进制素材，也不依赖 numpy。
- **限流从"建议"升级为"四层"**：事件采样（<620px 且 55% 概率）→ 全局预算（18/秒，
  step 计 1、其余计 3）→ 池化轮转 → 距离衰减。只做其中一层，150 只同屏时必糊成白噪声。
- 热键没做：项目里 `hotkey_*` 配置项只是存值，从未注册系统钩子。要做真正的全局热键
  需要 Win32 `RegisterHotKey` 或第三方钩子库，属于新增依赖 —— 用托盘菜单替代。

**验收**：500 次连发在预算 10/秒下恰好触发 10 次。

## 不建议做的（结论不变）

- **高清逐帧序列图**：6 状态 × 12 帧 × 3 体型 ≈ 200+ 张，且换速度段就得重画；
  程序化骨架已覆盖，收益为负。
- **3D 模型 + OpenGL**：与 QPainter 覆盖层管线冲突，俯视角下观感提升有限。
- **成虫展翅飞行**：视觉冲击最强，但会让一部分用户真的反感 —— 产品定位问题。这次没做，
  需要你单独拍板。

## 落地后浮现的两个真问题（原评估没预料到）

1. **主循环没调 `entity.update()`**。动画、僵直计时、梳理倒计时全靠它推进。
   没有它，上一轮做的肢体动画在真实运行里等于零，且近距离会被永久僵直。
   这是"方案评估"永远看不出来的东西 —— 只有真的把它跑起来才会暴露。
2. **"权重插值"不等于"持续跟随"**。姿态层每帧从固定基线重算，权重再高也只是部分偏移。
   凡是"朝向类"参数（触须、视线、身体前倾）都要区分**基线**与**当前值**，
   否则调参数会一直"差一点"。
