# 互动与氛围层实现说明

> 五个方案（触须嗅探、足迹油渍、抓取挣扎、真实进食、程序化音效）已全部落地，包含
> 你点名的两项"负面效果"（音效扰民、痕迹脏屏）—— 都保留，并各自配了关闭入口。
>
> 本文只写实现与验收；参数表、性能实测、已知限制都在后半段。

---

## 0. 顺手修掉的一个致命 bug

实现过程中发现主循环 `RoachApp._on_tick()` **从未调用 `entity.update(dt)`**。后果：

- 肢体动画在真实运行时根本不推进（只有离屏预览工具在跑，那里是手动调 `update`）；
- `FREEZE` 状态的 `freeze_timer` 永远不减，蟑螂被鼠标贴近后会**永久僵直**；
- 梳理触角、蜕皮、恐慌倒计时全部不生效。

现在主循环第 3 步统一推进所有存活实体，顺序是
`行为决策 → 运动积分 → 实体自身推进（动画/计时器/拖拽弹簧）→ 代谢`。
`tools/interaction_test.py` 与 `tools/smoke_test.py` 都已覆盖这条路径。

## 1. 触须跟随光标「嗅探」

**数据流**：`BehaviorSystem._handle_cursor_perception()` 每帧把 `threat_vector` 更新为
"光标 − 蟑螂"，**不设半径门槛**；距离只映射成 `threat_proximity`（0~1），
`Cockroach._update_antennae_aim()` 用它换算触须的跟随权重。

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 跟随权重 | `0.30 + 0.70·prox + 0.25·alertness`（上限 0.97） | 感知半径内 prox≈0.85~1，几乎精确指向 |
| 双侧分离 | ±0.22 rad | 两根触须分开追踪，形成立体定位感 |
| 探嗅微动作 | 0.35~0.6s，触须频率 4.2→6.8Hz，身体前倾 1.5px | IDLE 决策点按 55% 概率触发 |
| 预警窗口 | 0.12s | 光标进入 `r_panic` 时触须先收（目标 1.72 rad），随后才 FREEZE |

**验收**：鼠标绕蟑螂做圆周（半径 260px，5 个方位），触须平均朝向误差 **最大 13.5~18°**
（要求 < 25°）；预警窗口内触须后伏发生在第 0~2 帧，身体僵直在第 7~8 帧
（相差 ≥6 帧 ≈ 0.1s，恰好是"看得见顺序"的下限）。

> 测量本身有个坑：两根触须是 `aim ± 0.22`，当期望方向落在 ±π 附近时它们分别落在
> −179° 与 +179°，朴素算术平均会给出 0° —— 凭空造出 180° 的假失败。必须用圆周平均
> （`atan2(Σsin, Σcos)`）。这个问题只在随机初相撞上"光标在正后方"时出现，约 50% 概率，
> 表现为测试时好时坏。

## 2. 足迹与油渍

**事件链**：

```
LegRig._update_leg()  摆动相 -> 支撑相 的那一帧
      -> LegRig.plant_events (体坐标 x, y, 侧别, 落点力度)
Cockroach._local_to_world()   （与 render() 的变换链逐项对齐：rotate -> translate -> scale）
      -> app._on_footstep   -> OverlayWindow -> TrailCanvas.add_footprint()
```

落点力度由摆动结束时的抬腿量决定，轻放与踩实自然区分；被拎在空中时（`flail`）不落笔。
腹部油渍由 `Cockroach._emit_trails()` 每 1.4~3.2 秒发一次 `on_smear`，长轴沿前进方向。

**图层设计**（`src/systems/trails.py`）：

- 画布分辨率默认 **1:1**。实测 1920×1080 下"原分辨率直接合成"反而**比半分辨率更快**
  （≈0.5ms vs ≈0.8ms）—— 半分辨率要多做一次双线性放大。既然如此就没必要牺牲清晰度；
  4K 屏面积翻 4 倍时自动降到 0.5（`app.py` 里按 `宽×高 > 3.2M` 判断），内存从 33MB 降到 8MB；
- 淡出用 `CompositionMode_DestinationOut` 全幅填充做乘性衰减。**坑点**：8 位合成器按
  `round(dst·(1-a/255))` 计算，当 `a·dst/255 < 0.5` 时结果被舍回原值 —— 实测痕迹会永久卡在
  alpha=11 上。因此把逐帧衰减量**累加**，攒到 0.16（≈alpha 40）再统一填充：既能真正压到 0，
  又把填充频率从 60Hz 降到约 3.3Hz；
- 不做逐点回收：靠自然淡出，超过 `max_prints`（3000）时淡出速度 ×4，长时间无新增（1.6×淡出时长）整层清空；
- **落笔不再逐个建 `QPainter`**：200 只同屏时每秒上千次落地，逐枚建/毁 painter 要 2~8ms/帧。
  改成先入队，在 `tick()` 里一次画完（`_pending_fp` / `_pending_sm`），整帧只开一个 painter；
- `count` 是"当前存活笔数估值"，随淡出一起衰减（否则一旦历史累计破 3000，就永久停在加速淡出状态）；
  累计值在 `total_prints`，给验收用；
- 托盘「🧹 擦掉桌面痕迹」+ 设置面板同名按钮，用户觉得脏屏时可一键清空。

> **以前看不到这些痕迹**：旧版每帧 `setMask()` 会把窗口裁成蟑螂的包围盒，整层足迹全被裁掉。
> 现在改用 `WM_NCHITTEST` 命中测试（见 [`performance.md`](performance.md)），足迹铺满整屏也能正常显示。

**验收**：行走 3 秒落笔 74 枚（`total_prints`）；16 秒后图层归零。视觉上身后约 2~3 秒的行程内能看到连续足印链，
再往前已经淡到不可见 —— 不会把桌面糊成一片。
**开销**（1920×1080、2355 笔，实测区间）：原分辨率淡出 **0.03 ms**（攒帧后按 3.3Hz 摊薄）
\+ 合成 **0.45~0.65 ms** ≈ **0.5~0.7 ms/帧**；半分辨率是 0.01 + 0.82 ≈ 0.83 ms。
合计不到 16.7ms 预算的 5%。

## 3. 抓取与挣扎

- **命中与抓取**：`OverlayWindow.mousePressEvent` 命中实体且该实体有 `begin_drag` 时进入拖拽
  （食物等无此方法，仍走原来的点击逻辑）。悬停时光标换成手型，这是"可以捏"的唯一提示。
- **位移**：`Cockroach._tick_interaction()` 里用临界阻尼弹簧（k=260, c=2√k）跟随光标，
  不是硬绑定 —— 所以甩动时身体会晃。`MovementSystem` 对 `DRAGGED` 实体**完全跳过**积分，
  否则趋边性与边界反弹会和拖拽打架。
- **挣扎姿态**：新增 `flail` 姿态通道，允许"脚踩不到地但仍在蹬"（步态相位不再需要真实速度推进）；
  同时 `tremor=0.5`（六足高频抖）、`ant_freq=30`、`ant_wave=0.48`（触须各自狂扫）、腹部抽搐。
- **影子**：被拎起时影子位移 +7px、缩放 ×1.16、透明度 ×0.55，是"离开桌面"的唯一视觉线索。
- **松手**：`alertness += 0.5`，进入 PANIC 1.5s，并有 0.2s 的六足外展（`_splay_boost`）。
- **装死**：拎住超过 6 秒转瘫软（`dead=0.55`、`flail→0`），松手后先瘫 0.9 秒再逃。

**验收**：按下即 DRAGGED；拖到 (539,339) 时实际位置误差 9.1px；松手后 1 秒内速度 390px/s（要求 >200）。

## 4. 真实进食

- `Food` 新增 `nutrition` 语义（原有营养量现在真的会减少）、`ratio` 体积比例、
  `eaters` 位点表与 `eating_slots`（营养 ≥30 的食物 2 个位点，否则 1 个）。
- 位点用 2.5 秒心跳续期：个体死亡或被吓走不再续期，2.5 秒后自动释放，不会永久占位。
- 进食时停在 `max(32, 0.62×体长)` 处 —— 这个距离是为了让**头够到食物**，
  而不是把食物压在身体下面（第一版用 20px，食物整个被躯干盖住了）。
- 每 0.4 秒咬一口：`food.consume(6)`、`roach.feed(eaten)`、`roach.bite()`（腹板收缩脉冲 + 咀嚼声）。
- 姿态：`hold=1.0` 把两只前足收到口器前小幅搓动，躯干纵向做 1.00~1.03 的呼吸式缩放。
- 食物渲染：体积按 `0.45 + 0.55×ratio` 缩放，被啃时轻微晃动，边缘出现暗色啃痕。

**验收**：能量 40→75；营养比 1.00→0.00；食物最终消失；两只虫会分两侧进食（第二只拿不到位点就在外圈等）。

## 5. 程序化窸窣音效

`src/systems/audio.py`，首次运行时用标准库合成 4 段 WAV 到临时目录
（`%TEMP%/roachhub_sfx_v1`），不依赖 numpy、不需要用户下载素材：

| 音效 | 长度 | 用途 |
| --- | --- | --- |
| `step` | 45ms | 脚掌落地，音量 ∝ 落点力度 × 距光标距离 |
| `rustle` | 200ms | 受惊爆发冲刺 |
| `munch` | 70ms | 咬一口 |
| `thud` | 130ms | 被抓 / 松手落地 / 装死 |

四层限流，缺一不可：

1. **事件采样**：只有距光标 <620px 且 55% 概率抽样才发声；
2. **全局预算**：`step` 计 1、其余计 3，每秒合计不超过 `max_per_second`（默认 18）；
3. **池化复用**：每类 2~8 个 `QSoundEffect` 轮转，避免频繁 `play` 互相打断；
4. **距离衰减**：`prox = 1 - dist/700`，远处只留一层极低底噪。

无音频设备时 `available=False`，全部调用变成空操作，不影响模拟。

**验收**：连续请求 500 次，实际触发恰好 10 次（上限设为 10）。

## 5.5 抓取音效「你干嘛~哎呦」

`src/systems/voice.py` + `tools/prepare_voice.py`。素材是一段外部 MP3（爱给网下载），
132KB / 16.95 秒，但**真正有声音的只有前 3.88 秒**。

**为什么素材"看起来 17 秒、实际 3.9 秒"**

MP3 是 CBR 64kbps，**数字静音同样按 209 字节/帧占位**。所以 13 秒的空白照样吃掉 79KB。
`ffprobe` 报的 `Duration: 00:00:16.95` 是按码率估的，是对的；只是那 13 秒里没有一个非零样本。
判断有效区间必须靠能量阈值扫描，不能信容器时长。

**为什么不在运行时直接播 MP3**

`QSoundEffect` 只吃未压缩 WAV。MP3 得走 `QMediaPlayer`，启动延迟 100~300ms —— 抓取是
"手一碰就该响"的事件，等不起。所以做成构建期裁切：`tools/prepare_voice.py` 解码 →
取窗口 → 12ms 淡入 / 120ms 淡出 → 峰值归一化 → 写 `assets/sounds/grab.wav`（22050Hz 单声道，149KB）。

**裁切窗口：别用能量谷判断句子边界**

第一版按 20ms 能量包络切，把 1.88~2.12s 当成"换气间隙"，掐在 1.96s —— 结果「哎呦」整段
丢了。原因是**说话的停顿只掉到 -25~-30dB**，比静音高得多，看起来像谷、其实是音节过渡；
而拖长的单音（"哎——"）能量几乎恒定，反而容易被误判成伴奏。

可靠的依据是**基频**：浊音段自相关置信度 >0.55 且 F0 稳定在 130~340Hz，清音/静音/混响
会掉到 0.3。`tools/voice_sections.py` 按这个把整句分成段：

| 区间 | F0 | 内容 |
| --- | --- | --- |
| 0.18~0.29s | 334→311Hz | 高音起头（"你"），峰值 -26dB |
| 0.32~2.12s | 123~302Hz | 主体（"你干嘛"），峰值 -9.8dB |
| 2.22~3.18s | 97~216Hz | 长音（"哎——"），-17.6dB |
| 3.21~3.62s | 70~190Hz | 下行收尾（"呦"），-21.6dB |
| 3.77~3.90s | 71~240Hz | -32dB，混响/呼气尾巴，不要 |

默认取 **0.17s + 3.45s**（覆盖到 3.62s，再用 120ms 淡出吃掉尾巴）。要换裁切点不必改代码：
`python tools/prepare_voice.py --start 0.17 --length 2.0`，改前先跑 `tools/voice_sections.py` 看分段。

**播放策略**

- 按下即播，**从头播**（`stop()` 再 `play()`）—— 上一句没说完就又抓一只时是重来而不是叠加；
- 松手**默认不打断**。整句 3.45 秒，而实际拖拽绝大多数只有 0.3~0.8 秒；一松手就掐，
  等于「哎呦」永远听不见（这正是最初漏掉尾音后暴露的问题）。想要利落感的把
  `grab_voice.stop_on_release` 打开，就会恢复"松手即静音"；
- 120ms 防抖，防止双击 / 三击把同一句叠三遍；
- 托盘的**总静音**会连它一起压掉 —— 用户按了静音就该真的安静。

**为什么单独一个模块而不是塞进 `ScuttleAudio`**

|  | 窸窣音效 | 抓取音效 |
| --- | --- | --- |
| 触发频率 | 每秒几十次 | 偶发，用户主动 |
| 素材 | 程序化合成 45~200ms | 外部素材 3.45s（一整句）|
| 限流 | 必须，否则糊成白噪声 | 不需要，只需防抖 |
| 默认音量 | 0.45（底噪级） | 0.7（明确可闻） |
| 用户容忍度 | 高 | 低，必须有独立开关 |

两者唯一耦合的地方就是总静音。

**验收**：`grab.wav` 加载状态 `Ready`；素材时长 ≥3.4s 且 1.9~3.4s 段有声（卡"哎呦"是否被切掉）；
按下→`play`、默认松手不打断、勾选后松手→`stop`；总静音时无 `play`；连点 5 次只响 1 次。
**注意**：测防抖要打桩音频后端（`_effect`），替换 `play` 本身会把防抖逻辑一起替换掉，
测出来永远是"每次都响"。

## 5.6 蜕皮：为什么它有时是白色的

**白色不是另一个品种，也不是贴图错误 —— 是"刚蜕完壳"。** 每只若虫每长一龄都要蜕一次皮，
刚脱出来的新角质层还没硬化、色素也没沉积，整只是乳白半透明的（生物学上叫 teneral，
中文习惯叫"嫩壳"），过几小时才慢慢变深。桌面上把几小时压成几秒。

### 原来的两处破绽

1. **硬切**：`molt_timer` 归零那一刻贴图直接从 `cockroach_white_body` 换成正常的，
   颜色是"啪"一下跳回来的，看起来就像贴图加载错了；
2. **能跑**：蜕皮期间仍会被鼠标惊动。软壳个体以 430px/s 冲刺、身上还顶着蜕皮的姿势，
   是最穿帮的画面；而且用户很容易把"我一靠近它就变了"当成因果关系。

### 现在的做法

| 环节 | 实现 |
| --- | --- |
| 白化窗口 | `molt_timer` 2.2s（`MOLT_WHITE_SECONDS`），期间躯干用奶白贴图、整体 0.92 不透明度（新壳透光） |
| 颜色回落 | `teneral_timer` 比 `molt_timer` 多 1.4s；窗口结束后白贴图以 `smoothstep` 递减的不透明度叠在正常贴图上，颜色是**化开**的 |
| 软壳不能动 | `BehaviorSystem._handle_cursor_perception()` 见 `molt_timer > 0` 直接 return：只更新 `threat_vector`（触须仍会"感觉到"光标），不僵直、不避让、不逃 |
| 蜕下的空壳 | `Exuvia` 实体留在蜕皮位置，10s 内逐渐干瘪淡出；`interactive = False`，点它等于点空气，也不占种群上限 |
| 总开关 | `render.show_teneral`（控制台 → 🎨 渲染 → 「显示刚蜕皮的奶白色嫩壳」），关掉后蜕皮不变白，但空壳仍在 |

开销：白化叠加只发生在蜕皮刚结束的 1.4s 内，同屏通常十几只，每只多一次小贴图 `drawPixmap`，
实测对 200 只的帧预算无可测影响（`tools/smoke_test.py` 基准不变）。

**验收**（`tools/interaction_test.py` 第 12 组）：蜕皮期间鼠标贴脸后 `state` 恒为 `MOLTING`、
速度为 0；`teneral_alpha` 从 1.00 单调降到 0.00 且中途落在 0.15~0.85；蜕皮后留下恰好 1 具空壳、
`hit_test_at(空壳)` 返回 `None`、11s 后自动消失；关掉开关后不再变白。

对照图：`QT_QPA_PLATFORM=offscreen python tools/molting_preview.py` →
`tools/out/molting_preview.png`（白 → 70% → 40% → 15% → 正常色 + 空壳）。

## 6. 配置项

```toml
[interaction]
drag_enabled = true          # 关掉后点击蟑螂只惊吓，不再拎起来

[trails]
enabled = true
resolution_scale = 1.0       # 痕迹图层分辨率（0.25~1.0；4K 屏会被自动压到 0.5）
fade_seconds = 6.0
max_prints = 3000

[render]
show_teneral = true          # 刚蜕皮的奶白嫩壳（关掉后蜕皮不变白，空壳照旧留下）

[audio]
enabled = true
volume = 0.45
max_per_second = 18

[grab_voice]
enabled = true
volume = 0.7
file = "assets/sounds/grab.wav"   # 由 tools/prepare_voice.py 生成，不要手改
stop_on_release = false           # true = 松手立刻静音；false = 让整句「你干嘛~哎呦」说完
```

托盘菜单：`🧹 擦掉桌面痕迹`、`🔇 静音（全部音效）`。
设置中心新增 `🖱️ 互动与氛围` Tab，改动即时生效（`apply_runtime_settings`）。

## 7. 已知限制

1. **没有全局静音热键**：文档里提过 `Ctrl+Alt+M`，但项目当前没有任何全局热键实现
   （`hotkey_*` 配置项只是存值，未注册系统钩子）。要在任何应用前台都能静音，
   需要 `RegisterHotKey` 或 `pynput` 级别的钩子 —— 这次没做，替代方案是托盘菜单一键静音。
2. **痕迹是"自然淡出"而非"环形缓冲擦除"**：超过 3000 笔时加速淡出，而不是精确删掉最早的点。
   极端情况下（一只虫原地疯狂打转）会留下略深的局部油渍，但 1~2 秒内会淡掉。
3. **4K 屏上痕迹会降到半分辨率**：淡出成本按面积线性增长，3840×2160 的原分辨率淡出约 1.9ms/帧，
   为了守住 60FPS 会自动降级，足印边缘略软。
4. **音效依赖 QSoundEffect**：某些 Linux 无 PulseAudio 环境会加载失败并自动静音（有日志）。
5. **拖拽依赖隐式鼠标捕获**：拖拽过程中把光标甩出屏幕边缘会被夹在边缘 6px 内，不会飞出去；
   但如果拖拽期间用 Alt+Tab 切走，Qt 的隐式捕获可能丢失，松手事件收不到（再次点击即可恢复）。
6. **进食位点用 2.5s 心跳**：个体意外消失后位点最多被占用 2.5 秒。
7. **多屏未适配**：`window.multi_screen` 仍是占位配置，痕迹层只覆盖主屏。
8. **面板背后与任务栏上的蟑螂抓不到**：覆盖层在这两处主动"让位"（不画、不接管鼠标），
   否则蟑螂会压住面板文字、并且把托盘图标的点击吃掉 —— 用户看到的就是"右下角卡住、
   什么都点不了"。详见 `docs/console.md` 第 7 节。
