# 性能与「不卡死」护栏

> 现象：**不到 50 只蟑螂就开始屏幕闪烁、卡死。**
> 结论：闪烁和"卡死"是**三个独立原因**叠在一起，都不是"渲染太慢"。

实测环境：i5 级别 CPU（4.65GHz）/ 32GB / Win10 / **2560×1440** 单屏 / PySide6 6.12。

---

## 1. 闪烁的根因：每帧 `setMask`

旧版 `OverlayWindow.set_entities()` 每帧重建 `QRegion` 并 `setMask()`，30~60 次/秒。四个后果：

| 后果 | 表现 |
| --- | --- |
| 每次改窗口形状，Windows 重建 window region 并整窗重绘 | **屏幕闪烁** |
| 窗口被裁成一堆包围盒矩形，触须/腿伸出矩形就被切掉 | 肢体忽隐忽现 |
| 实体一多，矩形并集覆盖 67%~100% 屏幕（50 只实测已 67%） | 遮罩等于白算，且**整个桌面点不动** |
| 足迹层同样被裁掉，只显示在蟑螂包围盒里 | "桌面痕迹"根本看不见 |

### 改法：`WM_NCHITTEST` 命中测试

`src/utils/win_hit_test.py` 装一个 `QAbstractNativeEventFilter`，只在 `WM_NCHITTEST`（0x0084）时回答一句：

* 鼠标在蟑螂身上 → `return False`，交回 Qt 默认处理（`HTCLIENT`），正常收鼠标；
* 其它任何位置 → `return True, HTTRANSPARENT(-1)`，鼠标落到下面的桌面窗口。

它**只参与命中测试，不碰绘制、不裁像素、不重建窗口**。而且 Windows 对分层窗口本身就会把 `alpha==0` 的像素放过，所以绝大多数空白连问都不会问我们 —— 实测把光标移到空白处 `WM_NCHITTEST` 查询次数是 **0**。

为什么不用"像素 alpha 自动穿透"：足迹层是半透明的、且会铺满全屏，光靠 alpha 判定会让**桌面到处点不动**。命中测试能把"蟑螂"和"痕迹"区分开。20 万写法里这是唯一同时满足"痕迹可见"和"桌面可点"的。

代价：单次命中测试 200 只时 **0.046ms**（先用平方距离粗筛，再对候选做旋转椭圆判定），且鼠标不动就不调用。

> 非 Windows 平台保留 `QRegion` 遮罩兜底，但降到 **4Hz**（`tick_mask`），不再每帧。

## 2. 「卡死」的根因：定时器被量化 + 事件循环饱和

### 2.1 `QTimer` 默认是 `CoarseTimer`

Windows 系统定时器粒度 15.6ms，`CoarseTimer` 会把请求周期向它取整：

| 请求 | 实际 | 结果 |
| --- | --- | --- |
| 16.7ms（想跑 60FPS） | 15.6ms | 还行 |
| **33.3ms（想跑 30FPS）** | **46.6ms** | **"30FPS"实际只有 21FPS，且间隔抖动** |

修：`timer.setTimerType(Qt.PreciseTimer)`。同一台机器、同一份负载，p50 帧间隔从 46.6ms → **33.0ms**。

### 2.2 事件循环饱和 = 用户感知的"死机"

定时器按 16.7ms 排、一帧要 28ms —— 每次 tick 都迟到，消息队列里永远压着重绘，
于是拖窗口、点托盘要等几百毫秒。**CPU 只有 13%，但整机像死了**，就是这个原因。

修：**帧预算自适应**（`RoachApp._govern_frame`）。

* `budget_ms = 1000/target_fps` 是"期望"，达不成就降画质（LOD2→1→0）；
* `floor_ms = 1000/min_fps`（默认 30）是"底线"，达不成就继续降；
* 画质见底后把周期放到 `帧耗时×1.12`，**主动让出时间片**给输入事件；
* 连续 90 帧富余再逐档恢复，避免反复横跳。

> 早期版本把两者混用（都拿 16.7ms 当阈值），200 只时明明能跑 33ms，却被一路压到 14 FPS。
> 这是**自适应器自己制造的卡顿**，务必分清两道阈值。

## 3. 单帧开销：从 35ms 到 21ms（200 只）

| 项 | 优化前 | 优化后 | 手段 |
| --- | --- | --- | --- |
| 同类排斥 | 7.79ms | **1.45ms** | 空间网格（3×3 邻格），取代 O(n²) 全配对 |
| 足迹落笔 | 2~8ms | **1.25ms** | 攒一帧、一个 `QPainter` 画完（原来每枚足印新建/销毁 painter） |
| 六足 IK | 3.0ms | **1.6ms** | 去掉 `hypot`/`atan2`：`cos(base)=dx/d`，和角公式展开，原地写 `knee` |
| 触须链 | 2.4ms | **1.5ms** | 复用点数组（原来每帧新建 3200 个元组 → 20 万小对象/秒）、`exp` 提到 rig 层 |
| 绘制 | 18.7ms | **10.7ms** | LOD0 下只对**矢量肢体**关抗锯齿；躯干贴图仍保留平滑采样 |
| 托盘刷新 | 每帧 | **2Hz** | `QSystemTrayIcon.setToolTip` 每次走 `NOTIFYICON_MODIFY`，单次 5~30ms |

**绘制里为什么只关肢体的 AA**：六足+触须是 1~2px 细线，抗锯齿描边占全帧最大单项（200 只约 9ms）；
而躯干是旋转的照片贴图，一旦最近邻采样，边缘会明显锯齿跳动 —— 那个视觉损失大得多。

## 4. 现在的实测结果（2560×1440）

| 同屏只数 | 画质 | 帧率 | p95 帧间隔 | 卡顿(>250ms) |
| --- | --- | --- | --- | --- |
| 50 | LOD2（全细节） | **56 FPS** | 19.0ms | 0 |
| 100 | LOD1 | **32.6 FPS** | 35.0ms | 0 |
| 200 | LOD0 | **30.5 FPS** | 34.4ms | 0 |

200 只时一帧的构成：主循环 11ms + 绘制 15ms + Qt 清理/合成 ~7ms ≈ 33ms。

## 5. 怎么验证

```bash
# 真机浸泡（会真的开一个全屏覆盖层，跑完自动关）
python tools/soak_test.py --count 200 --seconds 8

# 帧预算拆解（离屏，逐阶段计时，含点击穿透的开销）
QT_QPA_PLATFORM=offscreen python tools/perf_probe.py --counts 50 100 200

# 主循环热点（cProfile）
QT_QPA_PLATFORM=offscreen python tools/sim_profile.py --count 200 --ticks 40

# 单只渲染拆解：影子/六足/躯干/触须各占多少
QT_QPA_PLATFORM=offscreen python tools/render_breakdown.py --count 200

# 回归护栏（31 项，含"不再 setMask"/"命中断言"/"帧预算降档"）
QT_QPA_PLATFORM=offscreen python tools/interaction_test.py
```

`soak_test.py` 的判据：任意帧间隔 > 250ms 记一次卡顿；p95 必须 ≤ `1.3 × (1000/min_fps)`；
运行期间窗口 mask 必须为空。

## 6. 已知限制

1. **4K 屏**面积是 1440p 的 2.1 倍，200 只大概会落在 15~20 FPS。届时把 `min_fps` 调到 24，
   自适应器会自动多降一档并守住不卡死。
2. **LOD0 无接触阴影**（`quality > 0` 才画）。200 只时阴影约 6ms/帧，取舍是"不掉帧优先"。
3. 帧率下限只保证**不卡死**，不保证"丝滑"。想更顺就减少同屏数量 —— 这是物理限制，
   不是可以靠调参绕过去的：一帧要画 200 只 × (6 足 + 2 触须 + 贴图)。
4. 自适应器的判定基于**帧间隔 EMA**，所以刚改完设置后的 1~2 秒内可能还有一次画质跳变。
