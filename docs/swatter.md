# 苍蝇拍 / 蟑螂拍：设计与实现

> 状态：**已实现**（P0 + P1 落地；含 §17.9 尺寸回调、§18 初版叫声、§19 换成 yamero、§20 换成短素材、§21 换成完整一句；P2 未做）
> —— 验收 `QT_QPA_PLATFORM=offscreen python tools/swatter_test.py`（60/60）
> 一句话：拿起拍子 → 拍面跟着光标（网格半透明，能看见底下的虫）→ 左键 70ms 下压 →
> 半径 44px 内的虫当场压扁爆浆 → 桌上留一摊污渍和一具抽搐的尸体 →
> 附近 240px 全部炸开逃窜 → 12 秒不挥拍自动收拍，桌面回到"能点"。

---

## 0. 先说结论（如果只读一段）

现有架构是"**只在蟑螂身上接收鼠标**"（`WM_NCHITTEST` + `HTTRANSPARENT`），这是这个项目的立身之本 ——
桌面图标、任务栏、浏览器都要能正常点。所以"拍子"不能做成常驻道具，必须是**显式的持拍模式**：

| 决定 | 取值 | 理由 |
| --- | --- | --- |
| 触发方式 | 托盘菜单 / `Ctrl+Alt+S` 拿起，再按一次放下 | 需要用户明确表示"我现在要打虫子" |
| 接管范围 | 整屏（**仍然让出**控制台面板与任务栏） | 空拍必须有反馈，否则挥空毫无手感 |
| 退出路径 | 热键 / 右键 / 12 秒闲置 / 隐藏蟑螂时 / 退出程序 | 少一条都会变成"桌面点不动了怎么办" |
| 命中判定 | 圆形，半径 = 44px + 0.30×体长（≈65px 体感） | 必须 ≥ 蟑螂的惊恐半径 55px，否则"贴上去它反而跑了" |
| 死亡表现 | 独立实体 `SquashedRoach`，`is_alive=True` 自管 22 秒 | `EcologySystem` 会在 `is_alive=False` 的下一帧直接删掉，没有尸体可画 |
| 爆浆 | 7 层叠加（污渍 / 颗粒 / 冲击环 / 白闪 / 震屏 / 音效 / 惊逃） | 单靠粒子不够"爽"，震屏与惊逃才是"手起拍落"的体感 |

## 1. 三条硬约束（读代码读出来的，不是猜的）

### 1.1 输入是"精确穿透"，不是普通窗口

`utils/win_hit_test.py` 里，`WM_NCHITTEST` 只在 `overlay.hit_test_at(x, y)` 命中实体时返回 HTCLIENT，
其余一律 `HTTRANSPARENT`。

**推论**：「随手在桌面空白处拍一下」这个动作，现在的架构**收不到** —— 那个坐标根本不属于我们。
要么整屏接管，要么接受"只能拍在虫身上才有效"（那样挥空毫无反馈，手感是死的）。

### 1.2 死掉的东西立刻被回收

```python
# systems/ecology.py
if entity.is_alive:
    survivors.append(entity)
else:
    on_entity_removed(entity.id)      # 下一帧就没了
```

**推论**：`roach.die()` 之后没有尸体、没有时间放特效。尸体必须是 `is_alive=True`、
自己计时到期的**独立实体**（和 `Exuvia` 一模一样的分身套路），而不是"死掉的蟑螂"。

### 1.3 绘制顺序按类名硬编码

```python
# overlay_window.py, paintEvent
if entity.is_alive and entity.__class__.__name__ == "Cockroach":
```

**推论**：新实体不加进这条 if 链，结果就是"逻辑上死了、屏幕上什么都没有" —— 而且不会报错。
这是本项目最容易踩的静默失败。

## 2. 交互设计：三个候选，选 A

| | A. 持拍模式（推荐） | B. 右键即拍 | C. 常驻道具 |
| --- | --- | --- | --- |
| 空拍能做吗 | 能 | 不能（空桌面收不到右键，除非整屏接管右键） | 能 |
| 默认是否打扰桌面 | 否 | 否 | **是**（永久接管） |
| 抢桌面右键菜单吗 | 不抢 | 抢 | 不抢 |
| 抓取功能 | 持拍期间临时停用 | 需改键位 | 需改键位 |
| 实现成本 | 中 | 中高（右键要单独一条穿透策略） | 低但产品上不可接受 |

**选 A。** 它唯一能同时满足"空拍要有反馈"和"默认不抢桌面"。
B 的问题是：要么整屏接管右键（那和 A 一样糟糕，还没法退出），要么空拍无效（手感死）。
C 直接违反 `docs/console.md` 第 7 节那条铁律，右下角会再次"点不动"。

### 2.1 持拍期间的用户协议

1. **显式**：只有用户主动拿起才接管，不存在"忘了关导致点不动"；
2. **可见**：拍子跟着光标 + 屏幕四周一圈琥珀色细边 + 托盘图标文案变成「放下蟑螂拍」；
3. **可退出**：五条路（见下）；
4. **有时限**：12 秒没有任何挥拍 → 自动收拍。

### 2.2 五条退出路径（全都要有）

- 再按一次 `Ctrl+Alt+S`（全局热键，应用没有焦点也生效）
- 托盘菜单「🔨 放下蟑螂拍」
- **右键单击覆盖层**（HTCLIENT 状态下右键也会投递给我们）
- 12 秒闲置自动收拍（`swatter.idle_disarm_seconds`，设 0 关闭）
- 隐藏蟑螂 / 清空生态 / 退出程序时强制收拍

> ⚠️ **Esc 收不到**。覆盖层是 `WA_ShowWithoutActivating` 且从不抢焦点（这是刻意的，否则打字都会被它吃掉），
> 键盘事件根本到不了我们。别把 Esc 写成唯一退路 —— 这是最容易想当然的一条。

## 3. 挥拍状态机

```
IDLE ──(托盘/热键)──> ARMED ──(左键)──> WINDUP 70ms ──> IMPACT(1帧) ──> RECOVER 200ms ──┐
  ^                     │                                                                  │
  └──(右键/热键/超时)────┘ <────────────────────────────────────────────────────────────────┘
                                   冷却 280ms（WINDUP 起算）
```

| 阶段 | 时长 | 视觉 | 逻辑 |
| --- | --- | --- | --- |
| ARMED | — | 拍面悬停在光标，影子偏移 (+10,+12)（悬空约 1cm），呼吸摆动 ±1.5°，跟随延迟 lerp 0.55 | 整屏接管鼠标；光标隐藏（BlankCursor） |
| WINDUP | 70ms | 拍面旋转 -38°→0°，影子收拢到 (+2,+2)，scale 0.94→1.06→1.0，叠 0.22 的运动模糊残影 | 不做任何判定（先动，后判） |
| IMPACT | 1 帧 | 拍面 scaleY 0.92（"压下去"）+ 白闪 + 冲击环 | **结算命中** → 生成尸体 / 粒子 / 惊逃 / 音效 |
| RECOVER | 200ms | 回弹过冲 → 复位 | 锁定输入（冷却的一部分） |

**为什么 70ms**：60FPS 下 70ms ≈ 4.2 帧，刚好能读出"手在动"；低于 3 帧读不出挥拍，高于 100ms
玩家会产生"我明明点到了"的挫败感。
**为什么冷却 280ms**：约等于人抬拍再落的节奏，同时防止按住连点把 200 只一拍清场。

## 4. 命中判定

### 4.1 几何

- **落点 = 光标位置**，不做偏移（"指哪拍哪"，任何偏移都会让人算不准）
- 判定：`dist(roach.pos, hit) <= head_radius + 0.30 * max(w, h)`，默认 44 + ≈21 ≈ **65px**
- 不判角度：拍面是圆的，做旋转椭圆只会让边缘判定变得不可预测

### 4.2 公平性（这段决定手感）

蟑螂的 `perception_panic_radius = 55px`：光标贴近 55px 时先 `begin_prestartle()` 僵直 **0.12s**，
然后才 430px/s 冲刺。

这不是障碍，而是**手感来源**：你贴上去 → 它先僵 0.12s → 你的 70ms 挥拍正好落在僵直窗口里 → 拍中。
玩家的体感是"我压住了它"，而不是"它瞬移了"。

反过来推：**判定半径必须 ≥ 55px**。小于这个数就会出现"我刚贴近它反而跑了"，非常难受。
默认 44 + 体型补偿正好压在临界线上；设置里允许 30~70 之间调。

远距离甩拍基本打不中 —— 这是对的，别做成"点哪死哪"。

### 4.3 多杀与上限

- 一次挥拍杀死半径内**所有**存活蟑螂，最多 **4 只**（防止有人把半径调到 70 后一巴掌清场）
- 尸体 / 卵鞘 / 食物不参与判定（尸体 `interactive=False`，不该被反复爆）
- **拖卵母虫**：连体卵鞘一起爆（`carried_ootheca.is_alive = False`、`is_carrying_ootheca = False`）
- **正在进食的虫**：`eating_food.release(roach.id)`，否则那个进食位点要白占 2.5 秒（见 trails 的 TTL 兜底）

### 4.4 拍空

没有命中也必须给反馈，否则挥空像点了张图：

- 地面灰尘环：半径 0→52，α 90→0，160ms
- `whiff` 气声（新增合成音，见 §9）
- 半径 180px 内的虫只加警觉（`alertness += 0.3`）与短促避让，**不**触发僵直狂逃
  （否则"我在旁边挥两下"就能把虫全赶走，变成赶虫器）
- **空拍不留污渍** —— 打空不该弄脏屏幕

## 5. 死亡与尸体：`SquashedRoach`

### 5.1 为什么不是 `Cockroach` 的子类

`MovementSystem` / `BehaviorSystem` / `ReproductionSystem` 全都按 `isinstance(e, Cockroach)` 筛人。
子类会被趋边性推着走、被当成可交配对象、被计入种群上限。**必须是独立类**，并且 `interactive = False`。

### 5.2 字段与生命周期

```python
class SquashedRoach(BaseEntity):
    interactive = False            # 点它等于点空气，也不进 hit_test
    # 快照：stage/gender/scale/angle/individual_tone/aspect
    lifetime = 22.0                # splat.linger_seconds
    twitch = 0.40                  # 前 0.4s 六足抽搐
    splat_seed                     # 预生成 5~9 个污渍斑点偏移，生一次不再变
```

`update()`：`age += dt`；`age >= lifetime` 时 `is_alive = False` → 交给现有的 `EcologySystem` 回收。
**不新增任何回收逻辑**。

### 5.3 渲染顺序（从下到上）

1. **主污渍**：不规则的 blob（3~5 个圆叠加成 path），`#6b4a24` α 0.55，带 1~2 条毛细拖尾
2. **压扁的虫体**：复用 `cockroach_*_body` 贴图，`scale(1.26, 0.46)`，叠一层暗褐（α 0.35）去掉光泽
3. **六足外翻**：6 条短线从体侧向外（30~40px），比正常步态更"摊开"；前 0.4s 以 60Hz 衰减抖动
4. **触须**：两条向两侧摊平的二次曲线
5. **体液高光**：2~3 枚浅黄小椭圆（`#c79a5a`，α 0.7）—— 这一层是"湿"的可读性来源，不能省

时间轴：`0~40ms` 纵向从 0.9 压到 0.46（"砸下去"）；`22s` 的 70% 之后开始淡出。
**碎屑不参与物理**：飞出屏幕外的浆点直接夹在边界内，贴边拍才有污渍可看。

## 6. 爆浆特效：7 层，缺一层都不"爽"

| 层 | 内容 | 时长 | 单次成本 |
| --- | --- | --- | --- |
| L0 主污渍 | 挂在尸体上的 blob，随尸体淡出 | 22s | 0（跟随尸体） |
| L1 体液颗粒 | 8~14 颗，扇形喷出 | 0.35~0.9s | 首次 0.3ms，之后衰减 |
| L2 冲击环 | 半径 0→1.6R 的圆环，α 180→0 | 180ms | 0.02ms |
| L3 白闪 | 落点径向渐变（Additive），α 90→0 | 40ms | 0.03ms |
| L4 飞溅进痕迹层 | 3~6 枚小斑点 + 1 条细拖尾 | 随痕迹层 | 摊销 0.03ms |
| L5 震屏 | 全场 3px / 120ms 衰减抖动 | 120ms | 0.01ms |
| L6 音效 | 合成 `splat`（湿爆） | 0.18s | 复用现有预算 |

**逻辑层（不是特效但最爽的一条）**：以落点为中心 **240px** 内所有蟑螂
`trigger_freeze_and_panic(...)`。拍死一只，全场炸锅 —— 这一条比所有粒子加起来都重要。

### 6.1 颗粒参数（别用重力）

- 方向：以拍击方向（光标位移向量；静止时用随机）为轴的扇形 **±100°**
- 速度 180~420 px/s，指数阻尼 τ = 0.16s，尺寸 1.5~4.0px
- 每颗带一条朝速度反方向的细线（α 0.4），读作"黏丝被拉断"
- 颜色：浆体 `#8a5a22` 主体 + `#c79a5a` 高光，2~3 颗用更深的 `#4a2c10`（沉淀）

> **为什么不用重力**：这是**俯视桌面**，重力方向是屏幕内法线。画"往下掉"会立刻穿帮。
> 落地感靠三件事读出：阻尼减速 → 椭圆变扁（`ry = rx * 0.55`）→ 变暗。

### 6.2 震屏必须只动绘制

`paintEvent` 开头 `painter.translate(dx, dy)`，**绝不改 `entity.pos`**。
否则蟑螂会被"震"进面板洞里、震到墙外，物理系统还要为此写一堆补丁。

## 7. 拍子的画法（程序化，不引入任何素材）

和项目其它部分保持一致：**不新增图片资源**，QPainter 现画。

- **网格拍面**：预渲染一张 QPixmap（椭圆 clip + 18×26 网格 + 包边），
  运行时一次 `drawPixmap` + `rotate`。**绝不在每帧循环 drawLine 400 次**（那是 3~5ms/帧）。
- **绘制尺寸 = `visual_scale` × 基准 168×208**（默认 0.70）。拍面必须**略小于判定圈**：
  判定直径 ≈ 131px，所以拍面宽 ≈ 118px。反过来（拍面比判定圈宽）会得到
  "看着整个盖住了它却没死"的错觉 —— 这是第一批实测截图里最刺眼的问题。
- **半透明 α 0.74**：透过网格能看见底下的虫。这不是妥协 —— 苍蝇拍本来就是透光的，
  正好解决"道具挡住目标"这个经典问题。网格线不透明度单独给 0.35。
  （α 0.82 实测太实，缩小后整只虫糊在下面只剩个影子，压到 0.74 才留得住轮廓。）
- **手柄**：QPainterPath + 线性渐变（暖木色 `#8a5f3c` → `#5c3a22`），握把 3 道防滑纹。
- **影子**：椭圆；待机偏移 (+10,+12) α 0.28（悬空），落下收敛到 (+2,+2) α 0.5。
  这是唯一的"高度"线索，没有它拍子像贴在屏幕上的一张纸。
- **运动模糊**：挥拍时把上一帧姿态再画一遍，α 0.22。
- **LOD0**（>110 只）：网格减到 8 条主筋 + 外圈。
- **光标**：`setCursor(Qt.CursorShape.BlankCursor)`，收拍**必须**还原成 ArrowCursor。

## 8. 输入层改造（最容易被低估的 30 行）

`ClickThroughFilter` 的回调只吃 `bool`，而 `hit_test_at` 返回的是实体。所以要新增一个门：

```python
def accepts_mouse_at(self, x: float, y: float) -> bool:
    """这个点要不要接管鼠标。持拍时整屏接管，但仍然让出面板与任务栏。"""
    ix, iy = int(x), int(y)
    if self._hole_region is not None and self._hole_region.contains(QPoint(ix, iy)):
        return False
    if self._work_rect is not None and not self._work_rect.contains(ix, iy):
        return False
    sw = self.swatter
    if sw is not None and sw.armed:
        return True
    return self.hit_test_at(x, y) is not None
```

然后把 `_init_window` 里的
`hit_test=lambda x, y: self.hit_test_at(x, y) is not None` 换成 `self.accepts_mouse_at`。

> 不改这一行，症状是：**空拍时点击穿透到桌面，把图标框选出来**。
> 程序不报错、拍子照样动，但每次挥空都在选中桌面文件 —— 典型的"能用但出戏"。

同时 `mousePressEvent` 要在最前面插一段：

```python
if self.swatter is not None and self.swatter.armed and event.button() == LeftButton:
    self.swatter.swing(event.position())     # 不走拖拽、不走 on_click
    event.accept(); return
if event.button() == RightButton and self.swatter is not None and self.swatter.armed:
    self.swatter.disarm()                    # 右键随时放下
    event.accept(); return
```

持拍期间 `drag_enabled` 临时失效（左键已经是拍子），但**不改配置**，收拍后自动恢复。

## 9. 音效：新增 2 个合成音

`systems/audio.py` 是运行时合成，加一条就行：

| kind | 长度 | 音色重心 | 包络 | 池 | 预算计 |
| --- | --- | --- | --- | --- | --- |
| `splat` | 0.18s | 1400Hz | 14 | 3 | 4 |
| `whiff` | 0.10s | 2600Hz | 22 | 2 | 2 |

- `splat`：低频 90Hz 冲击（前 30ms）+ 一段高通噪声爆裂 + 短尾巴 → "啪唧"
- 音量随本次击杀数上浮：1 只 0.42 / 2 只 0.52 / 3 只以上 0.6
- ⚠️ 改 `_SPECS` 之后 **必须把 `_VERSION` 从 `"v1"` 升到 `"v2"`**。
  缓存目录按版本号建，不升版本会一直播旧的临时 WAV，改了等于没改。
- 托盘总静音（`audio.enabled`）自动压掉，不需要额外开关。

## 10. 配置项

```toml
[swatter]
enabled = true                 # 总开关（关掉后托盘/热键都不可用）
head_radius = 44.0             # 拍面判定半径 (px, 30~70)
visual_scale = 0.70            # 拍子观感大小 (0.50~1.20)，只改画面不改判定
swing_ms = 70                  # 下压时长
recover_ms = 200               # 抬拍恢复
cooldown_ms = 280              # 两次挥拍最小间隔
idle_disarm_seconds = 12.0     # 闲置自动收拍（0 = 不自动）
splat_amount = 1.0             # 爆浆量倍率 0~2（颗粒数 / 污渍大小）
linger_seconds = 22.0          # 尸体 + 主污渍停留
max_particles = 14             # 单次击杀颗粒上限
screen_shake = true            # 命中震屏
scare_radius = 240.0           # 拍击惊逃半径（0 = 不惊动邻居）
can_squash_ootheca = true      # 能否拍爆卵鞘
count_kills = true             # 托盘/控制台统计"已拍死 N 只"
```

另有一组独立配置（与拍子本身解耦，因为它和抓取音效同属"人声"，扰民风险共担）：

```toml
[squash_voice]
enabled = true                 # 拍死时发出叫声
volume = 0.75                  # 0~1
variant = "myinstants"         # 完整一句 2.42s（默认）/ myinstants_short / yamero / aiyo
```

### 17.2 指标修正：颗粒绘制不是 0.25~0.40ms，是 1.1ms

§12 的估算**偏乐观了一个数量级**。240 颗颗粒的实测：3.9ms → 优化后 1.1ms。三条优化：

1. **颗粒关抗锯齿**：1.5~4px 的小点，AA 看不出差别，却占了 3.2ms；
2. **黏丝只给最大的那一撮**（`r >= 3.2` 且生命前 40%）：每颗都画要多 1.1ms；
3. **画笔 / 钢笔按 (色号, alpha 量化档) 缓存**：省掉每颗两次 `QColor`+`QBrush` 构造，约 40%。

冲击环与白闪另外加了**同位置去重**：一拍多杀时几个环几乎重合，叠 4 个不会更爽，只白花 0.3ms。

### 17.3 白闪必须收小：α 0.42 / 54px → α 0.20 / 38px

方案里按"屏幕是深色"估的。实际桌面上大半是浅色（资源管理器、浏览器），
加法混合的白盘在浅色底上会糊成一团白，看起来像 UI bug 而不是"啪"。
缩小并减半后，它在深色底上依然能读出曝光过度的感觉，浅色底上只是一层薄光。

### 17.4 尸体的两个画法坑

1. **污渍路径必须 `setFillRule(WindingFill)`**。`QPainterPath` 默认是奇偶规则，
   3~5 个圆叠起来时**重叠区域会被掏空** —— 一摊浆变成一朵花瓣，非常显眼。
2. **六足要画在躯干之前**。腿根坐标在体侧（`0.44 × 体宽`），画在躯干后面就会变成
   "压在尸体上的几条线"。触须也从 `1.55 × 体宽` 收到 `0.92`，否则像两根竖着的天线。

### 17.5 闲置收拍的口径：鼠标在动就不算闲置

方案写的是"12 秒没有任何挥拍"。实现时改成"**既没挥拍、光标也没动**"：蹲在那里瞄半分钟
把拍子收走，比"桌面点不动"更让人恼火。移动超过 3px/帧就重置计时。

### 17.6 关掉"连卵鞘一起爆"时，卵鞘掉在原地

`can_squash_ootheca = false` 不是"卵鞘跟着消失"，而是把它从母体尾部解下来、**落在原地继续孵化** ——
否则这个开关会变成"拍一只母虫顺便销毁一窝卵"，和"不爆卵鞘"的字面意思相反。

### 17.7 没做的（P2）

- 拍爆卵鞘的特殊表现（现在只是普通消失）；
- 3 秒内多杀的"×N"飘字；
- 拍面被浆糊住 / 需要"甩一甩"。

### 17.8 实测数据

| 项 | 结果 |
| --- | --- |
| 36 项离屏验收 | 36/36 通过 |
| 240 颗颗粒绘制 | **1.09ms/帧**（软件光栅，offscreen 实测） |
| 拍子（预渲染贴图 + 手柄，0.70 倍） | **0.36ms/帧** |

### 17.9 拍子太大：`visual_scale` 0.70（上线后按实机截图回调）

第一批实机截图里，拍面直径压了将近半个编辑器窗口，蟑螂只剩 40px 不到 —— **比例失衡**。

根因不是"画得大"，而是**拍面 168×208 比判定圈（直径 131）还宽 28%**：
玩家看着整只拍面盖住了虫、却判定未命中，体感上就是"拍子太大又不准"。

- 默认 `visual_scale = 0.70` → 拍面 118×146，**略小于判定圈**，"擦到边也算中"；
- 判定半径 `head_radius` 一点没动 —— 缩放**只影响观感**，手感参数与方案一致；
- 拍子变小后网格线从 1.0px 缩到 0.7px，抗锯齿下整张网糊成一片：
  `_head_pixmap` 里线宽改成 `1.0 / scale` 反算，实际落回 1px；
- 网面 α 0.82 → **0.74**。0.82 在缩小后几乎看不见底下的虫，与"透光网面"的初衷相反；
- 预渲染缓存 key 从 `detail` 变成 `(detail, 缩放档)`，否则改设置后位图被二次采样发虚；
- 控制台「🔨 苍蝇拍」页签新增「拍子显示大小 0.50~1.20 ×」+ 一段说明，
  这类主观参数不该逼用户改 `config.toml`。

## 18. 拍死音效：那半声「哎哟」

> ⚠️ 这一节描述的是**初版**的叫声。默认音效已在 §19 换成 `yamero`，
> 但素材（`squash_1~3.wav`）与这条处理链**完整保留**，设置里可一键切回。

> 追加实现于 2026-11-16。起因：「落拍有音效，但拍死时蟑螂自己没声音 —— 拖动它会说
> 『你干嘛~哎呦』，拍死却一声不吭」。

### 18.1 结论：不是新素材，是抓取那句的死刑版

抓取时播完整 3.45 秒（它还能抗议）；拍死时只剩 **0.25~0.44 秒的半声「哎哟」**，
音调被顶高 70~100%，尾巴是**硬切**的 —— 因为胸腔已经被压扁了。

选这条路而不是另找一声「啊——」，有三个理由：

1. **零新素材**：从 `assets/sounds/grab.wav` 同源派生，没有版权问题；
2. **叙事闭环**：抓的时候说得完整，是因为只是被拎起来；拍死只剩半声，
   玩家会自己补上这层因果。这比任何配音都好笑；
3. **音色一致**：听起来是同一只虫，而不是"又换了个音效库"。

### 18.2 处理链（`tools/prepare_squash_voice.py`）

    取「哎」起音 1.80s ─→ 重采样升调 ─→ 高通 240Hz ─→ tanh(1.7) 软削波 ─→ 6ms 硬切 ─→ 归一化 -2.8dB

| 变体 | 窗口 | 比率 | 输出 | 用途 |
| --- | --- | --- | --- | --- |
| `squash_1.wav` | 1.80s + 0.75s | 1.70 | 0.441s | 单杀主力 |
| `squash_2.wav` | 1.80s + 0.62s | 1.85 | 0.335s | 双杀第二声 |
| `squash_3.wav` | 1.80s + 0.50s | 2.00 | 0.250s | 三杀以上齐叫 |

两个必须强调的点：

- **起音必须正好从 1.80s 开始**。实测包络：1.82~1.96 是「哎」的起音短音，
  1.98~2.02 有个 -28dB 的字间谷，2.04 起才进长音。晚 20ms 就会把辅音吃掉，
  听起来从"哎"变成"啊"。
- **6ms 硬切是灵魂**。正常素材的淡出是 120ms，这里只给 6ms —— 它必须听起来
  是**被切断的**，而不是自己说完的。同时 6ms 足以避免爆音（末样本归零，
  验收里专门盯这一条）。

### 18.3 踩到的坑：高通设太高会把「哎」变成「滋」

第一版按"去掉胸腔共鸣"的思路把高通设在 320Hz，结果自相关置信度从源的 0.56
掉到 0.24 —— 因为源素材基频只有 **197Hz**，一刀切在 320 把基频压掉了 7dB，
只剩谐波，听感从"哎哟"退化成"滋"，词都认不出。

240Hz 在基频之上一点点：既削掉闷的胸腔音，又保住可辨识度。
同理 `drive` 从 2.2 收到 1.7 —— 2.2 会把元音削成方波，电子味盖过人味。

### 18.4 时序：人声比「啪叽」晚 25ms

`splat` 在 0ms，「哎哟」在 +25ms。物理上先接触、后出声；听感上两个瞬态不会
叠成一团糊音。这 25ms 是刻意留的，不是延迟补偿。

> 顺带说明：`splat`（拍面接触的合成音）和 `squash_voice`（虫子的惨叫）
> **必须同时存在**。只有「啪叽」像在拍一块肉，只有惨叫像在拍空气。

### 18.5 多杀不能变成噪音墙

| 击杀数 | 行为 |
| --- | --- |
| 0（拍空） | **不叫**，只有 `whiff` 气声 |
| 1 | 1 声（变体 1） |
| 2 | 2 声，错开 80ms（变体 1 + 2），避免同相位叠成怪声 |
| 3~4 | 2 声**同时**起音（变体 1 + 3），音高不同所以不糊，读作"一片惨叫" |

外加 **1 秒内最多 4 声**的硬预算：连拍 10 次最多 4 声。没有这条，连续挥拍
就是一群鸭子在叫。音量按击杀数上浮 0% / 10% / 20%，但不超过 1.0。

### 18.6 验收

`tools/swatter_test.py` 新增 `[18]` 8 项（当时总计 44/44，§19.7 已扩到 50/50）：

- 三个变体的**时长 0.20~0.50s / 峰值 0.70 / 末样本归零 / 起音 10ms 内出声**；
- 调度表：0→无声、1→[(25,0)]、2→[(25,0),(105,1)]、3→[(25,0),(25,2)]；
- 预算：连拍 10 次只排入 4 声；开关关掉 / 音量为 0 时返回 0。

⚠️ 一条判据写错过，记在这里：**爆音只看最后一个样本是否归零**，不能看
"末尾 64 个样本的峰值" —— 6ms 淡出本来就是渐降的，那里还有一半幅度，
按后者判会误报（第一版就误报了 3 个变体）。

试听页：`python tools/squash_preview.py` → `tools/out/squash_voice_preview.html`
（三个变体 + 用 Web Audio 复现「啪叽 + 25ms 后哎哟」的真实叠加）。

### 19.1 这次的改动不是"换素材"，是"换素材的**长度量级**"

| | 初版「哎哟」 | 现在「yamero」 |
| --- | --- | --- |
| 时长 | 0.25~0.44 秒 | **1.10~1.38 秒** |
| 来源 | `grab.wav` 派生（自己产的） | 外部 `yameroooo.mp3` |
| 处理 | 升调 + 高通 + 软削波 + 6ms 硬切 | **只裁切 + 变速 + 淡入淡出** |

时长差 3~5 倍，意味着**原来那套调度规则全部失效**。如果只换 WAV 不改代码，
症状会是这样：连拍 3 次，三声 1.38 秒的人声完全重叠 → 一团糊；双杀错峰 80ms →
两句几乎同时起音 → 听起来像一个人被加倍了，而不是两只虫。

三处必须改（都在 `squash_voice.py`）：

1. **双杀错峰 80ms → 469ms**（`_echo_ms()`，按最长变体的 34% 算，限制在 80~500）。
   0.3 秒的素材错开 80ms 是"两声"，1.38 秒的素材错开 80ms 只是一个更响的同一声。
2. **1 秒预算 4 声 → 2 声**。4 × 1.38 秒 = 5.5 秒的声压在 1 秒里，必然糊。
3. **同变体重触发不再 `stop()` 重播，改为换空闲实例**。这条是"长音的专属问题"：
   `QSoundEffect` 一个实例只有一条播放线，`stop()` + `play()` 会把上一声**从中间掐断**。
   0.3 秒被掐听不出来；1.38 秒被掐就是"ya… ya… ya…"的结巴。
   所以每个变体开 2 个实例轮换，最多 2 声并存，第 3 声才回头打断最早那个。

### 19.2 为什么不做"完整人声"的那两步处理

初版的**高通 240Hz + tanh 软削波**是给"被压扁后挤出来的半声"用的 —— 那是音效，
需要失真来读作"挤压"。完整一句人声是**台词**，加了失真就是玩具音，梗反而没了。
所以 `prepare_yamero_voice.py` 只做：裁切 → 变速 → 淡入淡出 → 归一化 -2.8dB。

### 19.3 解码这个 MP3：一个不报错的死锁

给 `QAudioDecoder` 设 **22050Hz / 单声道** 输出格式时，`bufferReady` 永远不触发，
`finished` 也永远不来 —— 脚本就挂在那里（本工具第一版真卡了两次 120 秒）。
同一个文件改成请求 **44100Hz / 立体声**，0.1 秒跑完。

**这是一条"什么都没发生也没报错"的坑，值得单独记住**：
把采样率交给 Qt 转，某些组合下就是零输出。现在的流程是
`解码 44100 立体声 → 自己下混 → 隔点抽成 22050`。

另外两个排查过程里排掉的可能，一并记下（省得下次再试）：

- **不是封面导致的**。日志里会刷 `av1_mf / h264_mf / could not find any MFT`，
  那是 ffmpeg 在枚举视频解码器（这个 MP3 带一张 300×300 的 ID3 封面）。
  剥掉 ID3 头后**依然**在 22050 下死锁，文件保持原样读即可。
- **不是码率/版本奇怪**。帧头是标准 MPEG1 Layer3 / 128kbps / 44100Hz。

### 19.4 裁切点：0.00 ~ 1.38，尾音必须留

包络实测（20ms 窗）：

| 区间 | 电平 | 判断 |
| --- | --- | --- |
| 0.00~0.11 | -28 → -19dB | 起音很轻，但**切掉就成了"从半句开始"** |
| 0.12~1.21 | ≈ -10dB | 主体，最扎实的一段 |
| 1.22~1.26 | 衰减到 -32dB | 主体收尾 |
| 1.30~1.37 | 回到 -20dB | **尾音/混响**，比主体低 10dB |
| 1.38 之后 | -33~-39dB | 只剩房间底噪 |

切在 **1.38**（留尾音）：它让最后一个音节听起来是**说完的**。切在 1.22 会像被掐断 ——
讽刺的是，那正是初版「哎哟」刻意追求的效果，但对一句"台词"是错的。

### 19.5 三个变体只改音高，不改结构

| 文件 | 变速 | 时长 | 音高 | 用途 |
| --- | --- | --- | --- | --- |
| `yamero_1.wav` | 1.00× | 1.380s | 原调 | 单杀主力 |
| `yamero_2.wav` | 1.12× | 1.232s | +2 半音 | 双杀的第二声 |
| `yamero_3.wav` | 1.25× | 1.104s | +4 半音 | 三杀以上的第二声 |

变速用**线性插值重采样**（和初版一致）：时长与音高同时变，所以升调版天然更短，
错峰也自然收紧一点。不用 time-stretch —— 保时长变音高会做成"变声器"，不是"另一只虫"。

### 19.6 保留可切回，而不是覆盖

`SOUND_SETS` 里两组并存：

```toml
[squash_voice]
variant = "yamero"    # yamero（默认）/ aiyo
```

`set_variant()` 会**重建实例并清掉时长缓存** —— 错峰和试听间隔都按时长算，
缓存旧值会让新素材的节奏全错（0.44 秒的素材按 1.38 秒错峰，两声被拉开成两句独立的话）。

设置页「互动氛围 → 拍死音效」新增**叫声来源**下拉，改完保存即时生效。

### 19.7 验收

`tools/swatter_test.py` 的 `[18]` 扩到 15 项（总计 **50/50**）：

- 两组素材各自的时长区间 / 峰值 / 末样本归零 / 起音 10ms 内 / **削顶率 < 0.2%**（人声不能有削顶）；
- 错峰：yamero 组 ≈ 469ms 且落在 300~520；aiyo 组自动缩到 ≈ 149ms；
- 实例轮换：同一变体连发两次会用两个不同实例；两个都忙时第三声才打断最早的；
- 预算 1 秒 2 声；关开关 / 音量 0 返回 0；
- 真实实例加载 3 变体 × 2 实例，`set_variant("aiyo")` 后时长缓存跟着换（无音频设备则 skip）。

⚠️ 一条用例写错过：**不能用 `play()` 计数去验"实例轮换"**。`play()` 的延迟由
`QTimer` 承担，离屏跑测试时事件循环不推进，触发器根本不会执行 —— 计数永远是 0。
要验这件事必须直接调 `_fire()`。

试听页：`python tools/squash_preview.py` → `tools/out/squash_voice_preview.html`
（原始 mp3 对照 + 三个变体 + 用 Web Audio 复现「啪叽 + 25ms 后 yamero」、
以及双杀 469ms 错峰）。

## 20. 再换一次素材：0.60 秒的一声惨叫

> 追加实现于 2026-11-16。起因：「更换被拍死的声音」，素材是
> `C:/Users/wangben/Desktop/myinstants(2).mp3`（2.415 秒，从一段视频里剥出来的音轨）。

§19 已经把"换素材"的坑填过了（解码、变调、调度），但那次**时长差 3 倍**才逼出整套调度规则。
这次正好反过来：素材只有 2.4 秒，能切成比 yamero 更短的句子 —— 于是要处理的是**反方向**的问题：
短到可以密集连发时，原来"1 秒 2 声"的保守预算就过于吝啬了。

### 20.1 从 2.4 秒里切哪一刀

源素材的 10ms 包络（`tools/prepare_clip_voice.py --probe`）：

| 区间 | 电平 | 判断 |
| --- | --- | --- |
| 0.00~0.59 | -6~-11dB 连续浊音（过零率 0.10~0.21） | **能用的主体**，起音直接在中段，没有静音头 |
| 0.60~0.81 | -12 → -38dB | 真正的分句间隙 |
| 0.82~1.66 | -7~-10dB | 第二句，比第一句还响 |
| 1.67~1.72 | -18~-21dB | 短间隙 |
| 1.73~2.41 | -6~-17dB | 后面还有两三句，末尾硬切（最后一个样本 -948） |

切 **0.00~0.60**：它是一句完整的话，末尾正好落进间隙。虽然文件开头就是半句（第一个样本 -1727，
直接从浊音中段开始），但"被拍扁的瞬间"本来就该是硬起音 —— 只在前面补 3ms 淡入消 click。

**不能自动选窗口**：试过"取能量最大的 N 毫秒"，会切在音节中间。包络只告诉你"响不响"，
不告诉你"这一刀是不是切在字与字的缝上"，所以窗口必须人来定，工具只负责 `--start/--end`。

### 20.2 三个变体和 yamero 一样，只是更短

| 文件 | 变速 | 时长 | 淡出 | 用途 |
| --- | --- | --- | --- | --- |
| `myinstants_1.wav` | 1.00× | 0.600s | 55ms | 单杀主力 |
| `myinstants_2.wav` | 1.12× | 0.536s | 40ms | 双杀的第二声 |
| `myinstants_3.wav` | 1.25× | 0.480s | 30ms | 三杀以上的第二声 |

没有高通、没有软削波 —— 那是给"被压扁的哎哟"用的，这里是一个完整的人声句子，加失真反而像玩具。

### 20.3 预算必须跟着素材长度走（新）

原来的 `BUDGET = 2` 是按最长变体 1.38 秒定的保守值，对 0.60 秒的素材就太紧了：
连点四下只出声两次，手感上像"没反应"。改成按最长变体分档：

```python
BUDGET_SHORT = 4      # 0.75 秒以内
BUDGET_LONG = 2       # 更长
SHORT_CLIP = 0.75     # 分档阈值

@property
def budget(self) -> int:
    return BUDGET_SHORT if max(self._durations) < SHORT_CLIP else BUDGET_LONG
```

阈值 0.75 取在"半声惨叫（0.44）"与"完整一句（1.10）"之间 —— 这条线两侧的听感差别是
"能不能连着喊"与"必须说完再喊"。错峰仍是 `0.34 × 最长变体`，短素材自动缩到 204ms。

### 20.4 新增通用切素材工具

`tools/prepare_yamero_voice.py` 是**特化版**（窗口与比率写死、注释里带实测包络，
是这个素材的证据链）；新加的 `tools/prepare_clip_voice.py` 是同一个处理链的**通用入口**：

```bash

    --src "C:/Users/wangben/Desktop/myinstants(2).mp3" \
    --set myinstants --start 0.00 --end 0.60
# 加 --probe 只打包络不出文件；--ratios / --fade / --peak 都可改
```

复用 `decode_mp3 / resample / shape / write`（解码的坑都在 §19.2），只多了一层参数解析。
源文件归档在 `assets/sounds/myinstants_src.mp3`，clone 下来就能重跑。

### 20.5 默认值与下拉框改为表驱动

`SOUND_SETS` 旁边加了 `SOUND_SET_LABELS`，设置面板**按表建下拉**：

```python
for key, label in SOUND_SET_LABELS.items():
    if key not in SOUND_SETS:
        continue
    self.combo_squash_variant.addItem(
        f"{label}（默认）" if key == DEFAULT_SET else label, key)
```

以前是两行写死的 `addItem` —— 加素材组忘了补 UI 就是"选了但没效果"，这种错很难在测试里发现。
现在加一组只需改 `SOUND_SETS` + `SOUND_SET_LABELS` 两处，`DEFAULT_SET` 决定"默认"两个字落在谁头上。


## 21. 第三次换素材：从「0.60 秒」改成完整一句

> 追加实现于 2026-11-16。反馈：「音效不对，我要最开始的『啊哈』，加上最后面的『打咩打咩』的。或者直接完整的音频。」

§20 把窗口定在 **0.00~0.60**，理由是"末尾正好落进间隙"。问题也在这里：
那句话的**开头和结尾都不在 0.60 秒里** —— 用户记住的两个特征音（起手的「啊哈」、
收尾的「打咩打咩」）恰好被这一刀切掉了，中间留下的反而是最没辨识度的一段。

这是"用包络挑窗口"的固有缺陷：**包络只告诉你哪里能下刀，不告诉你刀下是什么内容。**

### 21.1 源素材的真实结构

`myinstants_src.mp3`（2.415s，22050Hz 单声道，峰值 0.508）按 -26dB 阈值分段：

| 区间 | 内容 | 依据 |
| --- | --- | --- |
| 0.00~0.72 | **第一句（啊哈）** | 连续浊音，-6~-12dB，末尾 0.69 掉到 -26dB |
| 0.69~0.81 | 真间隙 | 连续 6 帧 < -22dB |
| 0.82~2.41 | 第二句起连续四拍 | 段内只有浅间隙（-16~-21dB），没有真静音 |

四拍的具体位置：1.73~1.81 / 1.90~1.98 / 2.05~2.20 / 2.21~2.41。
前两拍短（≈80ms）、后两拍长 —— 正是「打·咩·打·咩」的节奏，**最后那句在 1.71 之后**。

所以两件事同时成立：完整音频 = 啊哈 → 中间一句 → 打咩打咩；而裁剪版应该取 `0.00~0.70` + `1.71~末尾`。

### 21.2 两条路都做，默认走完整版

| 素材组 | 窗口 | 三个变体时长 | 说明 |
| --- | --- | --- | --- |
| `myinstants`（默认） | 0.00~2.415 | 2.42 / 2.16 / 1.93 | 原样，一头一尾都在 |
| `myinstants_short` | 0 + 1.71~末尾，段间 100ms | 1.51 / 1.34 / 1.20 | 只留啊哈和打咩打咩 |

默认给完整版：**不用赌哪一刀是对的**。剪辑版作为第二项，嫌 2.4 秒长就切过去。

段间不做交叉淡化 —— 这是两句话，本来就不连续；插 100ms 静音比硬接更像"换了口气"。

### 21.3 2.4 秒的句子不能按「1 秒 2 声」跑

§20 引入的分档只看"短 / 长"两档，2.4 秒会被归进"长"（2 声/秒 + 469ms 错峰）。
实测代价很直接：**每句只有前半截能被听见**。第二声在 1.0 秒处起，正好压在
第一声的 1.71~2.41（打咩打咩）上，两句的结尾互相抵消；连拍 14 次（4.2 秒）会排出 8 声，
其中 5 声是互相咬着的残句。

于是加第三档「完整一句」：

```python
LINE_LONG = 1.45       # 超过它就算"一句完整的话"
LINE_COOLDOWN = 0.85   # 喊到 85% 之前再拍不响

@property
def budget(self):      # 完整一句 1 声/秒
    ...
```

- **多杀只叫一声**：2.4 秒叠两句，听到的只有一句的前半 + 另一句的后半，不如让一句话说完；
- **冷却 0.85 × 时长**：最后那句「打咩打咩」落在 71%~100%，0.85 正好收在它之后。
  取 0.62 会"打咩刚起头就被顶掉"，取 1.0 又浪费（尾音只剩淡出）；
- **不 `stop()` 重播**：靠冷却挡，而不是靠打断 —— 打断就是永久听不到结尾。

同口径复测（每 0.3 秒拍一次，共 4.2 秒）：

| 素材组 | 档位 | 出声次数 |
| --- | --- | --- |
| `myinstants` 2.41s | 完整一句 | **2 声**（每 2.05 秒一句） |
| `myinstants_short` 1.50s | 完整一句 | **3 声** |
| `yamero` 1.38s | 中素材 | 8 声（维持 §19 的老行为） |
| `aiyo` 0.44s | 短素材 | 14 声（每次都响） |

阈值 **1.45** 卡在 yamero（1.38）与剪辑版（1.51）之间：前者是"一句短喝"，能叠；
后者已经是完整一句话，叠了就互相咬尾。

### 21.4 试听按钮只播一个变体

完整一句三个变体连播要 7.4 秒，中途停不下来 —— 点一下"试听"就是 7 秒的惨叫，
体验上等于"点了就后悔"。所以 `preview()` 在 `long_line` 时只播第一个变体（原调）。

### 21.5 `--join`：切素材工具支持多段

```bash
# 完整一句
.venv/Scripts/python.exe tools/prepare_clip_voice.py --src assets/sounds/myinstants_src.mp3 \
    --set myinstants --end 0 --fade 0.120,0.100,0.080

# 啊哈 + 打咩打咩
.venv/Scripts/python.exe tools/prepare_clip_voice.py --src assets/sounds/myinstants_src.mp3 \
    --set myinstants_short --join "0:0.70,1.71:0" --gap 0.10
```

`--end 0` = 到文件末尾；`--join` 每段写 `起:止`，止写 0 表示一直到末尾。
两段之间插 `--gap` 秒静音，再走同一套变速 / 淡入淡出 / 归一化。

加 `--wave tools/out/voice_short.png` 会另存一张"包络 + 采用窗口"对照图
（`voice_full.png` / `voice_short.png` 就是这么来的）：说"不是这句"时，
指着图报秒数比读表格快。

> 注意：`--wave` 会建 `QGuiApplication`，**不要**加 `QT_QPA_PLATFORM=offscreen` ——
> offscreen 平台没有字体（`QFontDatabase.families()` 返回 0 个），画出来全是方框。

### 21.6 验收

`tools/swatter_test.py` `[18]` 扩到 20 项（总计 **60/60**）：

- 四组素材（含新裁剪版）的时长区间 / 峰值 0.72 / 末样本归零 / 起音 10ms 内 / 削顶 < 0.2%；
- 新增"完整一句：多杀也只叫一声""冷却期内再拍不响""冷却 = 0.85 × 时长""冷却过后能再喊"；
- 真实实例：默认组 `myinstants` 2.41s / 冷却 2.05s / 预算 1 声；剪辑版同样走完整一句档；
  yamero 仍在中素材档（2 声 + 469ms 错峰），**没有被这次改动带到**。

设置面板：下拉四项，默认选中 `myinstants`；内存代价 = 3 变体 × 2 实例 ≈ **560KB**
（素材 22050Hz 单声道，三个变体共 280KB，解码后与文件同大小 ≈ 106/95/85KB 每份）。
